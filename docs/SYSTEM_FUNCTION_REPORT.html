条件可用 企业与多版本能力

核心结论：系统的可靠性不建立在“生成更长、更聪明的命令串”上，而建立在显式状态、能力门控、单步执行、后验验证、持久引用和人工接管上。即便模型服务不可用，离线规划、模型库、诊断、批任务和本地分析仍可独立工作。

02 · Product boundary

产品定位与边界

系统是什么

  • 面向 Windows + SolidWorks 的交互式桌面智能体。
  • 简单零件自然语言建模、计划预览、逐步执行和失败恢复工具。
  • 本地零件、装配体、工程图的索引、参数库和派生工作台。
  • SolidWorks 内嵌 Task Pane、事件桥和版本能力检测器。
  • 模型健康、装配、工程图、制造检查和批处理的统一应用层。

系统不是什么

  • 不是绕过确认、无限重试的一次性宏执行器。
  • 不是通过鼠标键盘坐标模拟 SolidWorks 操作的 RPA。
  • 不是 PDM 替代品；PDM 接口仅定位为只读查询。
  • 不是任意复杂曲面/扫描/放样/孔向导的通用重绘器。
  • 不是把相似度或参数哈希当作几何等价证明的系统。
责任边界：模型负责提出结构化建议，本地验证器、能力矩阵、执行状态机和用户确认拥有最终控制权。写操作只能由 Python STA COM Worker 执行；C# Add-in 只采集事件与上下文。

04 · Architecture

系统架构与进程边界

系统采用桌面主进程、独立 STA COM Worker、SolidWorks 进程内 C# Add-in 三个运行边界。三者只交换可序列化数据，COM 引用不会跨进程传播。

交互层
PySide6 UI：四个工作区、自定义标题栏、菜单、计划预览、进度、恢复、活动审计和实时上下文。
应用编排层
ApplicationController：异步请求号、Qt 信号、互斥任务槽、统一停止、后台线程、旧版迁移和 UI 状态同步。
领域服务层
Planning / Execution / Library / Advanced / Automation：计划协议、状态机、后验、模型库、工程服务、任务租约和能力门控。
基础设施层
SQLite / DPAPI / JSONL / Audit：设置、历史、模型库、批任务、语义索引、配方、能力证据和脱敏日志。
SolidWorks 边界
Python STA Worker 是唯一写执行器；C# Add-in 负责 Task Pane、应用/文档事件、轻量上下文和能力反射。

05 · User interface

界面与交互结构

主界面为无系统标题栏的 PySide6 桌面窗口，默认 1540×900，最小 1220×760。左侧固定导航、中部工作区、右侧活动与审计面板，低频能力收纳到顶部菜单。

四个工作区

  1. 智能建模：需求、计划进度、二维预览、步骤表、执行、命名目标和失败恢复。
  2. 本地模型库：扫描/深读、搜索、分页、Manifest 详情、安全派生和诊断。
  3. 自动化中心：持久任务、暂停/继续/取消、能力实验、示教与回放。
  4. 历史与诊断：时间、状态、需求和错误记录。

全局右侧面板

  • 当前运行状态与操作反馈。
  • SolidWorks 活动文档、配置、选择数和连接/忙/过期状态。
  • 最多保留 3,000 个界面日志块。
  • “清空界面日志”只清 UI，不改变持久审计或历史。

顶部菜单

菜单功能
文件新任务（Ctrl+N）、本地模型库（Ctrl+L）、退出
设置模型服务、API Key、Document Manager 许可证密钥

帮助日志位置、关于

反馈原则

  • 点击生成后立即禁用重复提交并显示阶段和秒数。
  • 缺失尺寸显示“需要补充建模条件”，不冒充模型调用失败。
  • 未知总量使用活动进度，已知文件数使用确定进度。
  • 错误以内联卡为主，只有阻塞确认使用模态对话框。
  • 模型过程展示可记录阶段、参数和校验，不展示内部思维链。
  • 颜色不是唯一状态信息；同时显示文字状态。

06 · Planning

智能规划系统

在线模型规划

  • 兼容 OpenAI Chat Completions 的 HTTP/HTTPS 服务。
  • 发送用户需求、工具 schema 和必要上下文；不发送 COM、数据库连接或 API Key。
  • 禁止重定向；使用系统 TLS 信任；模型超时可配置为 1–300 秒。
  • 响应必须解析成 JSON Plan，未知字段、未知工具和未知参数均拒绝。
  • 模型修复只允许替换失败步骤及其后缀，成功前缀不可被改写。

本地离线规划

  • 无模型服务时支持基础圆、矩形、圆柱类需求。
  • 能区分半径/直径并要求明确拉伸深度。
  • 关键尺寸缺失时最多提出三个澄清问题，不猜测数值。
  • ISO 4762 M3–M12 内六角圆柱头螺钉采用确定性参数表，不依赖模型自由发挥。
  • 计划通过后生成本地二维轮廓和特征摘要，仅作为执行前预览。

计划数据契约

对象字段约束
Planid、task、created_at、steps任务不能为空；至少 1 步；最多 500 步；未知字段拒绝。
ToolCallid、tool、arguments、description参数必须可 JSON 序列化；NaN/Infinity 和非支持类型拒绝。
ModelSnapshot连接、文档、草图、实体数、特征数、体积、面积、质量、选择数、时间质量不可用时以 mass_available=false 表示，不能把 0 当真实质量。
StepResult成功、消息、错误码、数据、前后快照、耗时API 成功但后验不成立仍为失败。

07 · Tool protocol

公开建模工具协议

模型可见工具共 14 个。文件派生、Pack and Go、导出、产品族、工程图和装配配合属于应用内部命令，不直接暴露给模型。

工具用途与主要参数本地前置/后验
session.ensure连接或启动 SolidWorks后验必须检测到连接。
document.new_part新建未保存零件同一计划只能建立一个文档；必须出现新的零件标题。
document.open_readonlypath静默只读打开；必须返回目标文档路径。
selection.planefront / top / right先有可写零件；后验选择数大于 0。
sketch.begin在 front/top/right 基准面开始草图不能嵌套活动草图；后验进入草图编辑。
sketch.begin_face在上一建模特征最外侧平面端面开始草图必须先有实体；按法向和距离解析端面，不依赖面序号。
sketch.circle中心坐标、radius_mm半径 0.0001–1,000,000 mm；实体数必须增加。
sketch.rectangle中心坐标、宽、高尺寸有界；生成中心矩形；实体数必须增加。
sketch.polygon中心、外接圆半径、3–128 边、旋转角生成闭合正多边形；用于端面后续切除等流程。
sketch.line起点和终点坐标拒绝重合端点；特征前检查直线轮廓闭合。
sketch.centerline起点和终点坐标同一旋转草图只能有一条中心轴。
feature.extrude深度、boss/cut、blind/mid_plane、reverse、merge切除前必须有实体；后验检查草图退出、特征/实体/体积变化。
feature.revolve0.0001–360°、boss/cut、reverse、merge必须有闭合轮廓和中心线；切除前必须有实体。
model.inspect只读当前模型状态不修改文档，用于重新快照与人工完成验证。
顺序校验：计划在进入 SolidWorks 前就会拒绝“未新建零件便选面”“没有活动草图便画几何”“开放直线轮廓直接拉伸”“没有实体便切除”“旋转缺少中心线”等语义错误。

08 · Execution and recovery

单步执行、验证与失败恢复

执行状态

idle→ready→running→completed
running→paused→running / aborted

“执行全部”并不是把整组命令提交给 SolidWorks，而是循环调用同一单步接口；每一步都重新经过参数验证、前快照、COM 调用、后快照和后验条件。

五种恢复方式

恢复方式行为安全限制
调整环境后重试用户修复模板、选择、文档状态或连接后重试当前步骤。同一失败指纹不能无限原样重试。
编辑参数并重试只替换失败 ToolCall 的参数，并重新走 schema 校验。未知参数、越界数值和无效顺序仍会被拒绝。
人工完成后验证用户在 SolidWorks 手动操作，系统仅采集新快照并验证预期变化。没有通过后验就不能标记成功。
让模型修复后续计划发送脱敏失败上下文，模型返回替代后缀。成功前缀不可替换；文件路径等模型绑定字段脱敏。
受控跳过记录跳过并继续。若后续特征依赖失败的轮廓/实体则拒绝跳过。

“停止全部”的真实语义

  • 立即让规划请求号失效，迟到模型响应不能改写 UI。
  • 设置模型库、分析、派生和持久任务取消信号。
  • 终止助手自己的 COM Worker，解除阻塞调用并阻止后续步骤。
  • 不会强杀用户正在使用的 SolidWorks 主进程。
  • SolidWorks 已经受理的同步原子 COM 调用可能在 Worker 终止前完成；继续前必须重新连接并重新快照。

09 · Local model library

本地模型库与参数库

模型库支持 .SLDPRT、.SLDASM、.SLDDRW，采用“文件系统快速扫描”和“SolidWorks 深度读取”两个独立阶段。

快速扫描

递归发现文件，记录规范路径、类型、大小、修改时间和快速指纹；完全不启动 SolidWorks。目录遍历不完整时不会错误标记缺失文件。

深度读取

逐文件进入 COM Worker，读取配置、属性、尺寸、特征、材料、方程、质量、几何摘要、装配引用和工程图页/视图。

无界面属性读取

配置合法 Document Manager 密钥后，不启动完整 SolidWorks 读取配置、属性和引用；结果标记为 metadata_ready，不冒充完整深读。

三种哈希

哈希用途不能证明什么
quick_fingerprint文件头尾分块和元数据，用于大量文件的快速增量发现。不能证明文件内容完全相同。
file_sha256完整文件哈希，用于深读跳过、写任务源版本锁和源文件不变验证。不能解释参数或几何差异。
manifest_sha256规范化参数 JSON 哈希，用于参数快照去重和变更检测。不能证明两个模型几何等价。

Manifest schema 2 内容

  • 路径、标题、文档类型
  • 配置列表与活动配置
  • 文档自定义属性
  • 配置级属性
  • 材料
  • 方程
  • 特征序列与错误码
  • 尺寸原始系统值
  • 识别长度的毫米显示值
  • 质量/面积/体积摘要
  • 装配组件与引用
  • 工程图页和视图
  • 几何摘要
  • 采集时间
  • 参数来源/完整度状态

增量与一致性策略

  1. 扫描阶段先更新快速指纹；文件变化则把参数状态标记为 stale。
  2. 深读前计算完整 SHA-256；只有完整哈希与参数状态均满足才跳过 SolidWorks。
  3. 读取前后再次计算完整 SHA-256；读取期间文件变化则丢弃 Manifest 并提示重试。
  4. Manifest 排除路径/标题/采集时间等采集元数据后规范化计算参数哈希。
  5. 相同文档与相同 Manifest 哈希不重复创建参数快照。
  6. 取消时保留已完成记录，但不做“未发现即缺失”的收尾。

模型库 UI

支持名称/路径搜索、每页 1–1000 条（默认 200）、上一页/下一页、扩展多选和完整 Manifest 详情。列表显示名称、类型、参数状态、参数哈希、大小和路径；扫描、深读、无界面读取、派生和分析共享互斥后台任务槽，避免同时写库或占用 Worker。

10 · Safe derivation

复制、参数派生、产品族、Pack and Go 与导出

统一发布模型：planned → staging → verifying → committing → succeeded/failed。任何目标都必须不存在；写入只发生在临时副本或临时目录；源哈希变化、API 非零状态、空输出或验证失败时不发布。
功能处理方法验证与限制
零件原样复制独占创建目标，分块字节复制并同步元数据。源/目标 SHA-256 必须一致；只支持 SLDPRT；失败删除目标。
零件参数派生先生成唯一临时 SLDPRT，修改 1–500 个毫米参数，重建、保存、重开并返回 Manifest。参数范围 ±1,000,000 mm；源哈希前后不变；目标不覆盖。
配置/产品族在隔离副本中创建配置矩阵、稳定尺寸列和配置属性。配置名/尺寸列一致性校验；逐配置激活、重建、保存与重开验证。
装配体 Pack and Go调用官方 Pack and Go，可包含工程图和 Toolbox 引用。输出不得越过临时目录；无空文件；至少一个 SLDASM；包哈希可复核。
工程图生成由 DrawingSpec 生成视图、剖视、BOM、气泡、模型尺寸并保存。父视图关系、本地化标准视图、BOM API 版本回退和重开 Manifest 验证。
安全导出使用 IModelDocExtension.SaveAs3 输出唯一临时文件，再发布。拒绝脏文档、格式错配、非零保存错误、空输出和目标覆盖。

11 · Engineering intelligence

诊断、搜索与工程自动化

模型健康诊断

统一 DiagnosticIssue，包含稳定规则 ID、严重度、范围、对象引用、证据、说明、建议和可自动修复标识；检查特征错误、引用、质量、材料/属性等。

参数快照对比

按尺寸、文档/配置属性、特征序列、材料和几何摘要分组输出差异；要求选择两个已读参数文档。

依赖与质量

解析装配组件和工程图视图引用，识别未入库、磁盘缺失、重复引用、压缩组件、特征错误和质量不可用。

相似模型

按特征类型、尺寸名称、属性字段和材料透明加权，用于候选排序；不会宣称几何等价。

本地语义搜索

把模型名称、材料、属性、特征等规范成字段词项，持久化本地索引；返回命中字段和得分解释，无网络仍可工作。

PMI / DimXpert / DFM

通过能力门控读取 PMI 记录；不可用时回退本地 DFM 规则并清楚区分“无数据”“不可用”和“检查通过”。

装配体助手

  • 读取组件路径、固定/自由状态、缺失引用和干涉结果。
  • 命名目标用 GetPersistReference3 保存，用 GetObjectByPersistReference3 恢复。
  • 配合请求包含两个持久引用、配合类型和对齐方式；当前实机验证覆盖平行配合。
  • 创建后以返回特征、重建状态和后快照作为证据，不只相信 API 布尔值。
  • 拓扑变化导致引用失效时暂停，不按面序号猜替代对象。

工程图自动化

  • 主视、俯视、右视和等轴测。
  • 带父视图约束的投影视图。
  • 基于模型包围盒生成剖切线和剖视图。
  • BOM 明细表及旧版视图 API 回退。
  • 自动气泡。
  • 模型尺寸导入。
  • PDF / DWG 输出。
  • 保存后重开 Manifest 检查。

PDM 与 Document Manager

两者都遵循显式只读边界。PDM 读取仓库状态、版本、检出与引用信息；Document Manager 在合法许可证下无界面读取元数据。许可证缺失、COM 未安装或成员不可用时，能力状态返回 unavailable，不会尝试写入或用空结果伪装成功。

12 · Persistent automation

持久批处理与人工操作学习

持久 Job / JobItem

任务能力

  • queued/running/paused/waiting_user/succeeded/failed/cancelled 状态。
  • 每个任务项具有顺序和幂等键。
  • 租约、心跳、尝试次数、恢复时间和错误分类。
  • 暂停、继续、取消、过期租约回收和崩溃恢复。

UI 能力

  • 运行排队任务、刷新、暂停、继续、取消。
  • 显示任务 ID、类型、状态、进度、成功、失败和消息。
  • “停止全部”请求所有未终结任务取消。
  • 当前 UI 尚无通用“新建任意批处理”编辑器。

当前自动化门禁包含 1,000 个独立任务项压力测试，覆盖逐项提交、幂等、租约、暂停/恢复/取消和统一停止。

人工操作示教

  1. 用户开始示教会话，并在 SolidWorks 中人工操作。
  2. Add-in 记录命令事件，系统保存步骤前后 ContextSnapshot 差异。
  3. 系统形成配方候选，初始状态为草稿/待审阅。
  4. 用户批准最近配方后才允许使用。
  5. 引导回放一次只显示一个目标、预期变化和操作建议，等待人工确认后进入下一步。
操作学习不是自动“录宏后盲重放”。配方包含文档类型、上下文约束、目标解析策略、风险和成功/失败统计；不同拓扑上下文不能直接复用持久目标。

多版本能力实验室

按 SolidWorks 修订号、Interop 版本、能力 ID、环境标签和证据记录结果，能力状态为 available/unavailable/unknown。它用于构建真实版本矩阵和发布门禁，不用“当前 Interop 有成员”替代完整夹具回归。

16 · Security and privacy

安全、隐私与防误操作设计

凭据

  • Windows DPAPI 当前用户绑定。
  • 不可解密时进入“需要重新输入”，不能保存空 Key 覆盖旧状态。
  • Authorization、API Key、Document Manager Key 和 DPAPI 密文不进日志。

网络

  • 只有点击生成/修复才调用模型。
  • API 地址必须是完整 HTTP/HTTPS URL，不能嵌用户名、密码或 fragment。
  • 禁止重定向、限制超时与响应大小。

文件写入

  • 源 CAD 永不作为目标写入。
  • 目标必须不存在，父目录必须存在。
  • 临时路径验证、源哈希锁、非空输出和发布后哈希。
  • 装配体必须 Pack and Go。

模型与 UI

  • 模型文本按纯文本渲染，不能注入 HTML。
  • 公开模型工具与内部写命令严格分开。
  • 恢复上下文对文件路径和凭据字段脱敏。
  • 不以命令字符串相同永久封禁几何操作。

风险控制重点

  • 同一 SolidWorks 命令在不同文档、配置、选择、拓扑和前序特征下含义不同，因此失败学习必须带上下文，不能建立全局字符串黑名单。
  • 环境/COM/超时/文件锁错误不能污染几何失败经验。
  • C# 事件、COM API 返回值、相似度和参数哈希都只是证据的一部分，不是单独成功证明。
  • 真实写测试必须使用临时夹具，不得直接使用生产 CAD 文件。

19 · User journeys

安装、配置与典型使用流程

开发环境启动

python -m pip install -e ".[dev]"
python -m sw_assistant

# 或双击
run.bat

模型服务在“设置 → 模型服务”配置；API Key 只显示输入框，不回显旧值。无在线模型配置时仍可使用离线规划和不依赖网络的本地功能。

典型流程 A：自然语言生成简单零件

  1. 在智能建模页输入尺寸明确的需求。
  2. 查看规划阶段、计划摘要、二维轮廓和工具参数。
  3. 选择“执行下一步”或“执行全部”；连续执行仍逐步验证。
  4. 失败时选择五种恢复方式之一。
  5. 完成后文档保持未保存，交由用户检查并决定保存。

典型流程 B：建立本地模型库

  1. 选择包含 SolidWorks 文件的目录，先执行“快速扫描”。
  2. 确认文件数量和状态后，再执行“深度读取全部参数”。
  3. 观察总数、当前文件、成功/跳过/失败、耗时和停止按钮。
  4. 通过列表检索、分页和 Manifest 详情检查参数。
  5. 按需运行健康、语义、相似度、依赖或快照对比。

典型流程 C：从已有模型安全派生

  1. 选择已索引模型并确认参数状态和源哈希。
  2. 零件可选择原样复制、修改副本参数或生成产品族。
  3. 装配体必须使用 Pack and Go；工程图普通复制被拒绝。
  4. 选择全新目标路径，等待 staging、验证和发布。
  5. 输出完成后复核目标哈希、Manifest 和源文件不变证据。

典型流程 D：人工介入后继续

  1. 系统在失败步骤暂停并保留成功前缀。
  2. 根据卡片提示在 SolidWorks 调整选择、模板、草图或特征。
  3. 点击“人工完成后验证”，系统采集新快照。
  4. 后验通过后继续；不通过则仍停留在恢复状态。

20 · Known limitations

已知限制与未验证条件

项目当前边界系统行为
复杂特征圆角、孔向导、曲面、放样、扫描、真实螺旋牙型尚未进入公开工具协议。不猜测重绘；优先复制/参数派生。
工程图复制普通工程图文件复制未开放。明确拒绝；使用工程图生成或格式导出。
多版本当前只实测 SolidWorks 2025 SP5.0。2024/2026 保持未验证，等待能力实验室实机回归。
PMI当前实机夹具不含 PMI。API 可调用但不把 0 条记录标记为完整验收。
PDM本机没有 PDM Professional COM。只读适配器返回不可用。
Document Manager需要用户自有合法许可证密钥。未配置时按钮禁用；不启动 COM 猜测。
批处理 UI底层为通用引擎，但尚无任意工作流的“新建批任务”编辑器。当前由健康诊断等已接入入口创建任务。
停止/回滚同步原子 COM 调用没有通用跨进程回滚。中断 Worker、阻止后续步骤并要求重新快照。
发布签名Setup 未使用商业 Authenticode。可安装但不能标记为已签名正式发行。
在线更新当前没有自动更新和日志自动清理门禁。由人工构建/发布流程管理。

21 · Recommendations

后续迭代建议

  1. 优先补齐多版本实机矩阵：2024/2026 的 Add-in 加载、模板、草图、旋转、Pack and Go、工程图和导出证据。
  2. 增加真实 PMI/DimXpert 与制造夹具：覆盖 GD&T、孔/基准、无效标注及 DFM 人工复核闭环。
  3. 建设通用批任务编辑器：在现有 Job/JobItem 引擎上提供工作流模板、输入预览、风险检查和逐项审批。
  4. 扩展可验证建模工具：优先孔向导、圆角/倒角、线性/圆周阵列；每项同时提交 schema、COM、后验、Fake 测试和实机夹具。
  5. 完善大型装配体验证：轻化、压缩、子装配、缺引用、Toolbox、多配置和性能基线。
  6. 企业集成沙箱：在合法 PDM Professional 与 Document Manager 环境完成只读权限/版本/引用矩阵。
  7. 发布工程：引入强名称和 Authenticode 私有签名流程、干净 Windows 用户 DPAPI 回归和安装升级测试。
  8. 可选语义后端：保留当前本地可解释检索，按需增加本地向量后端；向量结果仍需字段证据与参数状态。
建议维持的架构纪律：不要让 C# Add-in 承担写建模，不要让模型直接访问 COM，不要为“更自动”取消单步后验，也不要把 old/ 旧执行器重新接成新入口。

关键状态词

术语含义
ready计划已通过本地校验，尚未执行。
paused步骤失败或需要人工处理；成功前缀保留。
stale文件快速指纹变化，已保存参数可能过期。
metadata_readyDocument Manager 元数据可用，但不是完整 COM Manifest。
unavailable许可证、版本、文档类型或 API 能力明确不满足。
unknown尚无足够证据，不等于失败或可用。
persistent referenceSolidWorks 对选中对象的文档内持久引用；拓扑变化仍可能失效。
postcondition工具执行后必须从新快照观察到的真实变化。
lease持久任务执行权的限时所有权；过期后可安全回收。
