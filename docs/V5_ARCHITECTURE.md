# V5 持续建模任务架构

本文描述 5.0 基线。5.1 已改为一键持续任务和原生调查工具，当前设计以
[5.1 工作台](V51_AGENT_WORKBENCH.md)为准。

## 设计目的

V4.2 的 Pi 主要在失败后提出替代步骤。V5 的目标是让同一个持续任务根据实际执行结果推进建模：
已成功的动作与失败的动作都影响下一阶段，不以首次生成的固定计划作为唯一后续路径。

复杂建模中的问题可能来自选择、草图状态、实体拓扑、几何参数、文档变化或能力缺失。因此增加
Agent 不是无限重试的保证；改善效果依赖清楚的观察、受控动作、检查条件和可恢复任务状态。

## 职责划分

| 层 | 职责 | 不应承担的工作 |
| --- | --- | --- |
| 持续任务 UI | 需求、阶段、进度、动作、验收、人工反馈与恢复入口 | 推断 CAD 操作成功或绕过执行器 |
| 连续任务服务 | 生命周期、后台工作、状态快照、取消和持久记录 | 把迟到响应重新作为运行授权 |
| 任务决策 | 根据目标、实际状态和已执行结果提出下一阶段 | 获得任意代码、Shell、文件写入或直接 COM 权限 |
| 本地策略与执行器 | 工具 Schema、前置条件、串行执行、快照和后置条件 | 把模型的信心分数当作执行证据 |
| SolidWorks Worker | 真实 API 调用和实际状态读取 | 接受模型生成的任意脚本 |
| 任务存储 | 原子保存 JSON 快照和恢复所需进展 | 假定重新启动后 CAD 状态不变 |

Pi 可作为持久推理会话的运行时，V5 任务生命周期仍由本地应用管理。兼容固定计划入口保留原有
PydanticAI 初始规划、Pi 恢复和后备监督路径；这与持续任务入口应明确区分。

## 任务交互

1. 用户输入需求并准备任务，得到目标、假设和首个阶段。准备不产生 CAD 写操作。
2. 用户检查后选择持续执行或执行一个阶段。服务读取当前状态并决策，将获准动作交给执行器。
3. 执行器返回结构化结果和可验证证据；下一阶段使用这些结果继续决策。
4. 当需要人工确认，任务保持可恢复状态，界面显示问题与建议。用户完成检查并提供反馈后，服务
   保存反馈。用户再次点击执行时先重新读取并核对当前状态，再决定是否继续写入。
5. 任务完成需要验收结果。步骤列表耗尽或模型说“完成”，都不能单独代替目标检查。
6. 停止通过应用统一入口取消持续任务、固定计划、模型库和批处理。停止之后，迟到响应不能触发
   新的 CAD 写操作；已完成操作并不会因此自动撤销。

## 状态与界面约定

快照至少包含 `id`、`prompt`、`status`、`phase`、`message`、`rounds`、`goals`、`assumptions`、
`pending_steps`、`completed_steps`、`events` 和 `verification`。

| 状态 | 界面行为 |
| --- | --- |
| `ready` | 允许持续执行或执行一个阶段 |
| `running` / `busy=true` | 动态进度，锁定准备/恢复/重复执行，保持停止入口 |
| `review` | 显示人工建议与反馈输入，等待检查 |
| `completed` | 显示验收结果，停止继续执行 |
| `stopped` / `failed` / `interrupted` | 保留记录，展示人工反馈入口；重新核对后继续 |

按钮点击后立即本地锁定，不等待异步信号再禁用，以避免连续点击发起多个任务。
界面显示的是公开进展摘要、工具结果和检查结论，不显示原始隐藏推理。反馈文字不作为绕过本地
策略的授权；应以重新读取的实际模型状态为依据。

## 页面组织

主窗口保留“智能建模、本地模型库、自动化中心、历史与诊断”四个工作区。

智能建模默认展示持续任务：上方需求与恢复入口，中部状态和执行按钮，下方阶段动作、进展摘要和
目标验收。需要人工处理时才展开反馈区域。“建模 → 兼容固定计划”打开既有页面，原有模型库、
参数和自动化菜单继续保留。

任务面板依赖服务信号，不从 UI 线程直接操作 SolidWorks。模型等待期间显示动态进度；当前阶段
与轮次明确可见。所有文本使用现有深色配色与中文字体，动态错误和日志按纯文本显示。

## 数据隔离与兼容

V5 来自独立源码副本，默认使用 `%LOCALAPPDATA%\SolidWorksAIAssistantV5`。首次从旧版本复制
配置、模型库和历史后独立保存。任务记录位于 `tasks` 目录，采用原子 JSON 更新，避免只保存一半。
恢复任务只加载记录，必须重新检查当前 CAD 状态。

复制数据库不搬运 CAD 文件，也不自动修正其中的绝对路径。退出 V5 后从原 V4.2 目录运行即可
回到旧版本；V5 新增的任务与库数据不会自动反向合并。历史 `AGENT_VERSION_MIGRATION.md`
描述的共享数据目录方案不适用于 V5。导入报告位于 V5 数据目录的 `v4-import.json`。
部分失败时下次启动重试尚未存在的目标；成功复制的文件不会覆盖。如果失败后应用已创建同名
目标，保留目标并记录 `ExistingTargetPreserved`，需按报告人工核对，不能视为已完成导入。

事件桥继续消费现有共享事件目录，兼容已经注册的 C# Add-in。事件只是状态提示，执行器仍需
观察实际文档。两个独立版本不能因共用事件目录就并发修改同一个 SolidWorks 会话。

## 验证策略

UI 使用假 QObject 服务验证用户操作与状态显示，重点包括：准备不执行、立即防重复、统一停止、
人工反馈不自动运行、恢复中断任务不自动运行、进度显示、验收清单和异常后可继续输入。

服务与决策层需要另外验证多阶段成功反馈、失败恢复、预算、上下文变化、停止时的迟到响应和
持久记录。真实 Pi 与 SolidWorks 应使用隔离的新建未保存模型，分别验证通信与几何结果。

当前不编译 EXE。任意几何覆盖、完全自动回滚、正式 Pi 运行时随包分发、安装与目标机器实机
验收均不能仅凭界面或单元测试宣称完成。
