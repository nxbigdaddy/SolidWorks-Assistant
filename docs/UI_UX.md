# 界面与体验设计

## 1. 布局

使用无系统标题栏的 PySide6 原生界面：顶部品牌与菜单；左侧固定导航；中部当前工作区；右侧统一
活动与审计面板。高频操作在页面内，模型服务、数据目录、诊断和帮助收纳到菜单。

## 2. 页面

- 智能建模：需求输入、计划生成进度、步骤表、二维轮廓预览、执行控制和失败恢复。
- 本地模型库：目录管理、快速扫描、深度读取、停止、分页列表和详情。
- 诊断与搜索：模型健康、DFM/PMI、本地语义搜索、命中字段和处理建议。
- 自动化：产品族、装配体、工程图、批任务、操作学习/引导回放和版本能力实验。
- 全局上下文卡：显示事件桥、SolidWorks 版本、活动文档、配置、选择数、忙/过期状态。

模型库的快照对比、相似模型和引用质量检查收纳在“模型库”菜单，避免把低频工具全部堆到页面工具栏。
需要两个文档的对比使用 Ctrl 多选；分析放在后台线程运行，详情区显示结构化结果。
“停止全部”同时取消计划/执行、当前分析、模型库读取和所有未终结持久任务。
人工操作配方必须先审批；引导回放一次只展示一步的目标、预期变化和操作建议，不跨过人工确认。

## 3. 反馈规则

点击后立即改变按钮状态并显示阶段。未知时长任务使用活动进度条并显示秒数；已知文件数量使用
确定进度。错误以内联卡片为主，阻塞确认才使用模态对话框。失败信息必须包含发生位置、原因、
保留内容和下一步动作。

## 4. 配色与可读性

深色中性背景、蓝色主操作、绿色成功、琥珀等待、红色失败。正文和背景对比度满足常规桌面可读性。
所有控件使用微软雅黑 UI/Segoe UI；参数 JSON 使用等宽字体。不要用颜色作为唯一状态表达。

## 5. “思考过程”

界面展示模型请求阶段、耗时、计划摘要、校验项和工具参数，不展示不可验证的内部思维链。用户看到
的是系统能够记录、重放和解释的工作过程。

需求预检发现关键尺寸缺失时，进度卡改为“需要补充建模条件”，列出最多三个问题并保留原需求；这不
属于模型调用失败。提示卡内同时显示可编辑的多行补充输入框和“提交补充并重新生成”按钮；提交时把
补充内容追加到原需求，空内容不发起请求。原需求框保持可编辑，焦点优先落在补充输入框。计划通过
本地校验后，预览只绘制受支持的二维轮廓和特征摘要，不冒充最终三维模型。
