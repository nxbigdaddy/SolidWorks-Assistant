# 纯 Python SolidWorks 稳定自动化层

> 历史兼容层设计说明。本文中的原始坐标调用和多边形回滚描述不代表当前持续任务实现；
> 当前坐标转换以 V531_COORDINATES_AND_FEEDBACK.md 为准，稳定性验收以 V532_STABILITY_CONVERGENCE.md 为准。

## 1. 目标与边界

本项目的 SolidWorks 建模运行时只依赖 Python、pywin32 和官方 SolidWorks COM API。项目不加载第三方
建模 DLL，不使用 Python.NET，也不把外部函数库作为运行前提。稳定性机制全部保存在可审计、可测试的
Python 源码中。

核心原则：自然语言只生成受限工具计划；COM 调用串行执行；选择对象按几何意图重新解析；每个写操作都
核对实际结果；失败后根据模型是否已经变化选择回滚、暂停或重建后续计划。

## 2. COM 所有权与串行执行

- 所有 SolidWorks COM 对象只存在于独立 Worker 进程的主线程。
- UI 和规划进程只发送 JSON 可序列化的 `ToolCall`，不持有 `Face2`、`Edge`、`Feature` 等 COM 对象。
- Worker 使用项目自有命名互斥锁 `SolidWorksAIAssistant.Automation.SerialGate`，避免两个助手实例同时
  改变活动文档或选择集。
- 每次工具调用都在同一个锁范围内采集前快照、执行 COM、采集后快照，避免快照与写入被其他实例穿插。
- 成功和失败路径的后快照都在锁释放前采集，失败恢复逻辑不会把另一个实例随后造成的变化误算到当前步骤。
- 超时只终止助手 Worker，不强制结束用户的 SolidWorks 进程。

## 3. 重建后的拓扑重解析

`feature.extrude` 完成并强制重建后，程序不保存 `Face2`，只保存可序列化的 `PlanarFaceSignature`：

- 活动文档路径、标题和配置；
- 来源特征名称；
- 平面包围盒中心和完整包围盒；
- 平面法向与面积；
- SolidWorks 持久引用字节（API 可用时）。

执行 `sketch.begin_face` 时：

1. 再次执行 `ForceRebuild3(false)`；
2. 尝试通过持久引用恢复面，并重新核对几何签名；
3. 持久引用无效或几何不符时，从来源特征当前的 `GetFaces()` 重新枚举；
4. 只接受唯一匹配，0 个或多个同等候选均暂停；
5. 选中后检查选择数量必须恰好为 1；
6. 目标使用后立即清除，不能在后续拓扑变化后再次复用。

这避免了最常见的随机失败：Python 仍持有旧 COM 包装对象，但 SolidWorks 重建后内部拓扑已经换代。

旋转中心线采用同一策略。`sketch.centerline` 只保存文档身份、`ISketch.Name`、草图持久引用、官方
`GetID()` 二元组、线段类型、两个端点、构造线属性和可用的线段持久引用，不保存 `ISketchSegment`。
关闭草图并重建后，先通过持久引用取得当前 `ISketch`；必要时再按名称找到草图特征并调用
`IFeature.GetSpecificFeature2()`，最后从当前 `GetSketchSegments()` 中解析唯一匹配的构造线。优先使用
所有 `ISketchSegment` 都支持的 ID/type，端点作为 `ISketchLine` 可用时的几何回退；重复中心线造成歧义时
停止，不按数组序号猜测。

## 4. 草图与特征验证

- `sketch.begin`/`sketch.begin_face` 建立只含文档路径、标题、配置、`ISketch.Name` 和可选持久引用的会话
  签名，不跨调用保存 `ISketch`。每次画圆、矩形、多边形、直线以及创建特征前，都重新取得活动草图并
  核对该签名。
- 用户切换文档、配置或活动草图后，当前坐标框架和中心线目标立即作废；程序在调用任何几何写 API 前停止。
- 拉伸不再允许在没有助手绑定活动草图时依赖残留选择创建特征。
- 草图坐标统一使用 `origin + x*u + y*v`，适用于前视、上视、右视和实体平面，不假设 `z=0`。
- 标准面公开坐标约定固定为 `front(x,y)->world(X,Y)`、`top(x,y)->world(X,-Z)`、
  `right(x,y)->world(Y,Z)`；因此右视面 `y_mm=90` 明确表示世界 Z=90 mm。
- 正多边形优先使用官方 `ISketchManager.CreatePolygon` 单次创建；只有运行版本/COM 包装没有暴露该方法时
  才逐边回退。回退中任一边失败都会选择删除本次新增实体，删除不可用时只对本命令执行有界
  `EditUndo2`，并读回草图实体数确认回到命令前状态。
- 创建圆或直线返回空对象时，先比较草图实体数量；必要时清除选择、临时启用 `AddToDB` 后精确重试，
  最后恢复原属性。
- 旋转草图和重解析后的中心轴使用官方 selection mark，并在调用前清除无关选择；进入特征 API 前严格
  验证选择总数为 2、Mark=0 草图为 1、Mark=4 中心线为 1。
- 关闭草图前调用官方 `ISketch.CheckFeatureUse`，分别按 boss/cut extrude/revolve 用途检查开放轮廓、
  自相交、零长度实体、错误共享端点以及轮廓穿越旋转中心线等问题。检查失败时草图保持打开，特征 API
  不会被调用；当前 COM 包装未暴露该方法时同样停止，不降级为无检查写入。
- 特征定义的 `AccessSelections` 显式传入 `VARIANT(VT_DISPATCH, None)`，避免 pywin32 把普通 `None`
  封送成错误 COM 类型；访问结束始终调用 `ReleaseSelectionAccess`。
- 拉伸完成后读取 `IExtrudeFeatureData2` 的深度、终止条件、方向和合并状态。
- 旋转完成后读取 `IRevolveFeatureData2` 的角度、方向和合并状态。
- Instant3D 使 `GetTypeName2()` 返回 `ICE` 时，改用 `GetTypeName()` 取得底层 Boss/Cut 类型。
- 每个新特征重建后调用 `IFeature.GetErrorCode2`；任何错误或警告都按失败处理并进入撤销路径。
- 实际特征定义与请求不一致时执行 `EditUndo2(1)`，随后强制重建；回滚失败则停止并要求人工检查。

## 5. 快照后验与安全重试

每步前后快照包含文档、活动草图、草图实体数、特征数、实体数、体积、面积、质量和选择数。API 返回对象
不等于成功；工具还必须满足对应后验条件。

失败时比较前后文档、草图、特征、实体和体积。只要失败调用已经改变模型，就禁止原样重试，避免重复
拉伸、重复切除或在残留选择上继续执行。用户可以先撤销/人工检查，修改参数，或根据当前模型状态重建
后续计划。失败指纹包含工具参数和当前模型上下文，不按单一命令字符串永久拉黑。

失败恢复先分类：暂时性错误只在模型状态已知且未变化时自动重试一次；几何、拓扑和能力错误只在同样的
安全条件下请求模型生成替代后缀。故障包包含前后快照、历史失败方案和坐标约定，且本地路径会脱敏。
自动替代后缀必须通过完整计划校验；每个计划最多自动修复两次。状态未知或模型已变化时自动化停止，
不会用 AI 猜测当前 SolidWorks 状态。

## 6. 当前验收边界

纯测试覆盖重建后获取新面/中心线对象、持久引用几何不符时回退、歧义面与歧义中心线拒绝、文档/草图
漂移拦截、开放轮廓预检、失败快照原子性、参数回读、回滚和变更后禁止原样重试。

2026-09-01 已在 SolidWorks 2025 SP5.0 的独立未保存零件中完成 14/14 场景实机矩阵：前/上/右基准面、
盲拉伸、中面、反向、拉伸切除、旋转凸台/切除、反向旋转、多级端面重解析、开放轮廓拒绝、定义不一致
撤销和跨文档漂移保护。机器可读证据及完整场景表见
`SOLIDWORKS_BASE_MODELING_STABILITY_2026-09-01.md`。

Worker 超时/强制停止属于进程恢复边界；其他 SolidWorks 主版本和白名单之外的复杂特征仍需各自能力矩阵。
实机测试不得直接使用生产 CAD 文件，也不能把“COM 返回非空”作为通过标准。
