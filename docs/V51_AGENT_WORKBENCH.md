# 5.1 持续 Agent 工作台

本页保留 5.1.0 架构基线。5.1.1 对时限、恢复、引用与调查预算的修正以
[当前修复记录](V511_RECOVERY.md)为准。

本轮不是增加某个手机或产品的专用流程，而是让同一个任务会话能够主动调查、依据结果决定动作、
修正可恢复错误，并保持用户目标与执行证据。目录仍为 `SolidWorks-Assistant`。
5.0 原始源码基线为 `2b6309d`，标签 `v5.0.0-baseline`；本轮分支 `codex/v5.1-agent-workbench`。

## 用户操作

1. 在默认任务对话中输入需求，点击“发送并开始”。程序在一个后台任务中准备并持续执行，不再
   要求逐次点击准备、执行。普通缺省参数可以声明合理假设；关键配合、精度、安全条件仍需确认。
2. 任务过程中继续输入补充要求，下一安全边界接收，未执行候选作废并重新规划；已成功步骤保留。
3. 对话显示公开的工作摘要、调查问题、工具结果和调整理由，不显示模型隐藏推理。
4. 真正需要人工处理时，界面展示阻塞原因、已调查内容和需要提供的信息。提交现场反馈后一次
   点击即可先核对现场、再继续。如果反馈新增尺寸或结构要求，勾选对应选项，使其进入需求记录。
   停止后的任务不能通过普通补充消息直接复活。
5. “高级操作”保留仅准备、单阶段、继续与记录恢复。恢复记录本身不执行；“停止所有”常驻。
6. 查看需求与验收：原始要求、子目标、关联指标、待绑定项和未完成证据分开显示，不使用虚假完成百分比。

## Agent 与宿主的职责

Pi 负责会话内自主选择调查问题、使用调查结果再判断，以及提出下一阶段动作。PydanticAI 后备
路径提供同名调查工具和持续上下文。本地运行器仍是唯一 CAD 写调度者，不能绕过工具 Schema、
文档身份、前后观察、几何后置条件和最终验收。

| 组件 | 实际实现 |
| --- | --- |
| 原生 Pi 调查 | 显式注册 `sw_investigate`，模型可在一次回复前连续调用调查工具 |
| 调查通信 | 通过已有 RPC stdin/stdout 的扩展 UI 请求/响应转发，宿主内部处理，不弹输入框、不打开 HTTP 端口 |
| 执行线程 | 调查回调在任务调用线程执行，保持 Worker 取消代次和串行边界；不另开并发 CAD 调用 |
| 白名单 | `--no-tools --tools sw_investigate`，关闭自动扩展/技能/上下文发现，只加载本应用提供器 |
| CAD 修改 | Agent 提出近期白名单动作，本地运行器独立校验并执行；调查桥拒绝任何写工具 |
| 停止与重启 | 取消后拒绝晚到工具请求；不同 Pi 进程使用不同消息队列，旧 settled 事件不能结束新请求 |
| 长会话 | PydanticAI 按完整用户回合裁剪，保留工具调用与结果配对，避免孤立 tool 消息 |

这里保留了 Pi 的原生工具调用与持续会话，但没有把独立终端的 Bash、任意读写文件、动态代码、
任意 COM 权限放进模型。也没有实现“模型自动修改本程序并加载新 DLL”。真正缺少工具能力时，
仍需受控开发、验证后扩展；不能用更多重试虚构能力。

RPC 和扩展方式以本机已安装 Pi 0.84.4 的实际源码为准，同时核对了官方
[RPC 文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/rpc.md)及
[扩展文档](https://github.com/earendil-works/pi/blob/main/packages/coding-agent/docs/extensions.md)。
注意该版本 `--no-tools` 会建立空允许名单，必须显式指定受信工具名，不能只调用 `setActiveTools`。

## 自主调查工具

| 工具 | 用途与边界 |
| --- | --- |
| `session.capabilities` | 本程序工具能力、当前连接与版本、API 成员可见性；成员存在不代表实际操作一定成功 |
| `model.references(limit)` | 基准面、平面面候选及持久引用/几何线索；只读，不改变选择 |
| `sketch.inspect` | 当前草图实体、构造线和轮廓检查；未知闭合状态不算有效轮廓 |
| `feature.inspect(name, limit)` | 精确名称特征的错误、尺寸和面；默认 30，最多 100，并明确截断 |
| `diagnostics.recent(limit)` | 从当前任务已有失败摘要寻找线索和建议调查方向；不扫描真实日志文件 |
| `model.observe` / `model.inspect` | 总体模型观察；状态读取失败与“数值为零”严格区分 |

新调查工具输出不超过 60 KB，桥接上限为 64 KB；非有限数值拒绝，过大结果明确要求缩小查询。
未知、部分结果与完整结果分开，不能把截断数据当作完整验收。整体快照失败时允许定点只读工具
继续排查，写工具仍保留严格前置检查。准备阶段的调查不会连接/启动 SolidWorks 或新建文档。

## 自主排错与必要暂停

普通候选参数不合法、已确认无模型变化的选择失败、可恢复前置条件错误、可核对文档内的读取
不足，先进入有界调查并把具体证据交回同一 Agent，再调整方案。普通缺省和能力疑问各有自主
处理机会，不直接把第一次不确定推给用户。

保留以下停止边界：文档身份不明、调用可能部分改变模型但无法验证、后置条件失败、越权操作、
关键人为决定缺失。暂停不等于自动撤销，已受理的同步 COM 调用可能执行至返回。

预算：默认 48 次阶段决策；每轮最多 8 次调查，全任务最多 96 次；重复且无新证据的调查会触发
无进展保护。目标是避免盲目循环，不是承诺任意任务都能自动完成。

## 原始需求与验收合同

原始输入生成带来源的需求记录，Agent 可以增加子目标、关联可读回的指标，不得偷偷删除原文、
移除已经绑定的指标或放宽验收范围。普通运行补充形成新的持久用户消息与要求，晚到旧决策不能
覆盖新意见。人工反馈原文也持久保存，澄清/能力反馈进入验收来源；安全现场确认与新几何要求区分。

最终完成要求：所有需求有指标映射；具体几何证据通过；活动草图已退出；特征无错误；文档身份
符合任务。只有文档类型/实体数量不够；模板基准面或原点不算本任务的实体几何证据；大容差不能
把正几何条件变成恒真。尚未知道真实名称的尺寸/特征可以待绑定，但未取得真实观察不能通过。

这是可追溯的机械证据门禁，**不是任意产品外观语义的数学证明**。Agent 仍可能拆解不充分或误解
需求。体积相同也不代表外形相同，复杂外观、孔位与结构齐全仍需要具体子目标及更丰富观察/验收。
已有精确目标不能通过普通补充直接改写；与已锁定尺寸冲突时目前需另开新任务，不能悄悄覆盖。
目标版本修订入口尚未提供。

## 验证与未完成边界

开发门禁：`scripts/verify.ps1`。原生 Pi 集成测试只访问本地模拟接口，覆盖多次工具调用、后续决策、
PydanticAI 后备、上下文裁剪、停止和旧事件隔离。多任务与错误恢复由通用状态机夹具验证，不使用
产品名称分支。

`scripts/live_workbench_smoke.py --execute` 将真实 Pi、脚本化本地模型接口和真实 SolidWorks 连在一起：
查能力、新建隔离零件、拒绝错误基准面候选、读取真实候选、修正动作、建模并验收。此脚本只验证
通信/排错/执行闭环，不能证明外部大模型的自主规划质量。完整结果另见本轮验证报告。

本轮不编译 EXE，不打包完整 Node/Pi 运行时，不操作用户已有文件、不向外部模型提交真实 CAD 或
日志。圆角/抽壳等未封装能力、任意中间拓扑回滚、基于 CAD 模型截图的几何/外观验收和
外部模型复杂任务评测仍待扩展。
