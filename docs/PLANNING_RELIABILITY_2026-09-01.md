# AI 计划生成可靠性修复报告

验证日期：2026-09-01（Asia/Shanghai）<br>
范围：自然语言到白名单 `ToolCall` 的生成、校验、修复、诊断；不包含新的 SolidWorks 实机写入。

## 1. 故障证据与结论

同一需求“画一个iphone 14 Promax 手机”连续两次调用 DeepSeek 成功返回 13/14 步计划，耗时分别约
89.92 秒和 57.73 秒，但都在本地 `validating` 阶段失败：

```text
sketch.begin.plane: 参数必须是以下值之一：front, top, right。
```

日志中没有 `execution_started` 或 COM 网关错误，因此这不是 SolidWorks 选面、拓扑或 API 执行失败。
直接根因是 `choice("front", "top", "right")` 只存在于本地闭包校验器，旧的模型可见工具描述只暴露
`required/default/description`，没有暴露合法枚举。模型只能猜内部协议，完整响应结束后才被本地拒绝。

## 2. 已实现修复

### 单一来源工具 Schema

数字、整数、布尔和枚举验证器携带自身 JSON Schema；`ToolSpec.schema()` 输出标准对象约束：

```json
{
  "type": "object",
  "properties": {
    "plane": {
      "type": "string",
      "enum": ["front", "top", "right"]
    }
  },
  "required": ["plane"],
  "additionalProperties": false
}
```

同一份元数据同时服务模型提示和本地严格校验，类型、枚举、数值上下界不会再各自漂移。

### 有界参数规范化

规划器接受一组确定性别名并转换为内部值，包括：

- `Front Plane`、`前视基准面` → `front`；
- `Top Plane`、`上视基准面` → `top`；
- `Right Plane`、`右视基准面` → `right`；
- `拉伸凸台/拉伸切除` → `boss/cut`；
- `给定深度/中面` → `blind/mid_plane`；
- 中文“是/否” → JSON 布尔值。

别名表以外的值仍失败，且错误包含步骤序号、工具、字段、收到值和期望 Schema。

### 一次性定向修复

模型计划未通过校验时，系统定位失败步骤，保留之前已经验证的前缀，只提交失败步骤和剩余后缀做
一次修复。替代后缀与前缀重新运行完整参数及顺序状态机；修复后仍失败就停止，避免无界调用和重复
等待。

### 复杂需求预检

手机类需求在没有整体长×宽×厚或没有明确“无圆角简化主体”范围时，直接返回
`planning_clarification`，不调用模型。当前基础工具不支持的圆角、摄像头、按键和接口会明确说明，
不会由模型虚构尺寸或工具。原故障输入现在会进入可操作的补充条件状态，而不是等待一分钟后报错。
提示卡直接提供可编辑的多行输入框和提交按钮，补充内容会自动追加到原需求后重新生成；不需要用户
返回上方猜测应编辑哪个控件。

### 可恢复诊断

规划失败记录继续写入 `history.db`，但 `plan_json` 不再固定为空对象，而是保存失败计划和结构化诊断。
会话审计日志同时记录 `failure_id` 和诊断摘要；凭据字段仍由统一脱敏器过滤。

## 3. 自动化证据

- 复现式测试证明中文/英文基准面值会在执行前规范化。
- Schema 测试验证 `plane` 枚举、拉伸深度范围、布尔类型和禁止额外字段。
- 定向修复测试验证只保留有效前缀、只请求一次、二次失败后停止。
- 复杂手机请求测试验证缺少尺寸时供应商接口调用次数为 0。
- 历史与运行时测试验证失败计划、步骤、字段、收到值和期望 Schema 可恢复。
- 全量结果：`196 passed`；Ruff 通过；mypy 56 个源码文件零问题；compileall 通过。

## 4. 独立性与边界

本轮只修改 Python 源码、测试和 Markdown 文档，没有复制、加载或链接 01yx DLL。运行源码、脚本、
测试和依赖清单中没有 01yx、Python.NET、`import clr`、`AddReference` 或自定义 DLL 加载入口。
运行源码目录 DLL 数量为 0；项目已有 143 个构建/发布 DLL 与本机 01yx 目录当前 6 个 DLL 的 SHA-256
相同数为 0。

本轮没有向外部模型服务发送新的实测请求，也没有启动 SolidWorks 写入。模型协议问题由捕获日志和
隔离回归覆盖；既有 SolidWorks 2025 SP5.0 的 14/14 基础建模实机证据保持不变。圆角、孔向导、
放样、扫描和曲面仍须先扩展白名单工具和对应实机矩阵，不能由语言模型绕过能力边界。
