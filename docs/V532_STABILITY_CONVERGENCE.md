# 5.3.2 稳定性收敛：范围、门禁与证据

日期：2026-09-07。活动项目：`SolidWorks-Assistant`。
原 5.3.1：`v5.3.1-baseline` / `3ee9498`；本轮分支 `codex/v5.3.2-stability-gates`。
不新增业务功能、不重写界面、不编译 EXE。目标是把可复现的问题挡在交付之前，而不是扩大能力承诺。

## 三层验收分别统计

1. **源码与故障边界**：离线单元、集成、模拟时钟及故障注入。证明实现符合测试中的规则，不等于实机可靠。
2. **确定性真实 CAD 合同**：不用模型，通过生产 spawn worker、checked_call 执行固定合成参数，
   独立读取草图坐标变换、线段/圆几何、实体位置/尺寸/体积和特征健康。保存重开另列证据。
3. **自主任务基准**：固定 10 个范围内任务，每个 3 次新会话为评测计划。只有真实推理、真实 CAD、
   宿主完成及独立验收同时成立才能统计为自主完成；脚本化回复和安全停止不能计为真实任务完成。

第 2、3 层未执行或缺少证据时必须标记 not_run/unverified，不能由第 1 层测试数量代替。
首期范围仍为单配置、无外部引用的新建零件，不代表任意装配、曲面、3D 草图或跨版本认证。

## 错误分类与有限恢复

原有不同失败共享“连续六次无进展”，现在由宿主按事件和结构化错误码分类。
不使用任意错误文案来判定安全可恢复，不授予模型新的权限。

| 类别 | 初始连续预算 | 处理 |
| --- | --- | --- |
| 协议/格式 | 6 | 要求修正回复，不占用几何探索次数 |
| 规划/已知几何失败 | 6 | 使用新证据调整方案，已知隔离候选可按原协议恢复 |
| 观察 | 3 | 获取有意义的只读证据，无法证明状态时暂停 |
| 环境 | 3 | 区分不可用会话与可证明未写入的拒绝，不自动重放未知调用 |
| 执行器契约 | 1 | 暂停故障能力，不让模型反复用参数补偿封装错误 |
| 安全/结果未知 | 立即暂停 | 保留现场，不重放、不盲目恢复未知候选 |

这些数字是初始有限策略，不是经实机优化得出的最佳值。全任务 round/action 上限保持。
不同类别交替失败不能绕开硬预算；调查、需求绑定、普通提示不重置错误窗口。
候选中间成功不代表正式进展，只有实际通过的非候选几何或正式提交才重置连续预算。
候选恢复不能洗掉分类计数、工具故障或人工检查状态。旧任务迁移保留保守边界，不自动运行。
显式提交人工反馈后，只有再次独立核对现场成功且不存在活动候选，才允许全任务一次额外纠正窗口。
该窗口仅适用于协议、规划、观察和环境；累计次数、全局轮次/动作上限保留。停止或重启不继承
尚未核验的重开授权。执行器契约故障与第二次预算耗尽会明确要求修复软件或新建任务。

网关新增结构化 `failure_category / contract_failure_code`。例如：

- 新实体为空、旧草图完整且未变、管理器设置恢复、无 COM 异常，才可标记 planning / creation_no_entities。
- 实际几何与请求不符或变换无法验证属于 adapter_contract。
- 文档、草图、配置或已有几何漂移属于 safety；即使 COM 同时异常也不降级为普通规划失败。

## 真实验收的现场保护

- 默认仅检查现场，不建模；`--execute` 才写入专用合成测试零件。
- 只有 `--start-solidworks` 才允许测试主进程启动尚未运行的 SolidWorks。
- 开始时任何已有文档都会阻止测试，不检查其几何、不关闭它们。
- 生产 CAD worker 采用 `allow_start_solidworks=False`，只连接测试已经确认的会话；
  会话消失时不能暗中启动替代实例。未知 COM 连接异常也不再自动 Dispatch。
- 实际几何通过独立只读 RPC 检验，不使用写入 applied 参数回显作为验收。
- 草图检查返回真正的 `ISketch.ModelToSketchTransform.ArrayData` 以及完整性标记。
  数组缺失、非有限数值或格式错误均不能作为已验证坐标证据。
- 所有新测试零件与原生检查点保留，失败不自动关闭、删除或继续不明现场。

## 开发验收入口

以下从活动项目目录运行。第一个命令只输出固定任务目录，不请求模型、不运行 CAD：

```powershell
.\.venv\Scripts\python.exe scripts/autonomy_benchmark.py catalog
.\.venv\Scripts\python.exe scripts/live_cad_contract_matrix.py --preflight-only
```

真实 CAD 矩阵必须显式授权执行，默认单项 `front.rectangle`；完整目录由 `--case all` 选择。
`--repeat` 为 1–3，改变固定位置与尺寸；`--verify-save-reopen` 另外验证原生保存、检查点哈希和
独立副本重开几何。每个包含保存重开的案例保留三个测试文档，失败立即停止后续格子，
所有证据写入 `artifacts/cad-contract-matrix/<run>/result.json`，记录源码与环境指纹。

```powershell
.\.venv\Scripts\python.exe scripts/live_cad_contract_matrix.py --execute --case all --repeat 1 --verify-save-reopen --start-solidworks
```

初始非空现场会阻止运行；文档保留后不能直接再跑来绕过保护。总预算 1800 秒，单次普通 RPC
120 秒。同步主线程 COM 头部查询不能强制中断；脚本不强杀 SolidWorks。
本轮尾部增加矩阵专用预算准入：普通写入前剩余时间必须超过 150 秒，candidate.begin 超过
210 秒，finish/restore 超过 270 秒（均为现有 RPC 完整时限加 30 秒余量）。不足则不提交下一次
写入，报告 `blocked / budget_boundary`，已完成案例保留，其余标记 not_run。到期已中断的调用
仍按未知结果处理，不会被改称“尚未执行”。该修复针对验收脚本，不等于生产所有耗时路径已优化。

自主任务评分器提供 `plan --environment <JSON>`、`template --manifest <JSON> --run-id <ID>`、
`score --manifest <JSON> --results <JSON>`。固定期望源于目录，不采信模型自行降低的目标。
30 个不同任务/会话及独立几何证据缺一不可，脚本后端、安全停止或人工辅助不计自主完成。
这是本地声明式证据审计，不是签名防伪系统；尚须授权执行器采集真实模型调用、曲面/贯通孔、
独立模型几何等证据，模板没有伪造读回数据。退出码：0 满足该命令；score 只有整批通过才为 0；
1 未通过或未执行；2 输入无效。

## 实测暴露的下一阶段工作

本机测试显示，除了恢复策略，**观察开销也会让一个阶段持续数分钟**。首格运行过程中，
`model.observe` 多为 2–10 秒；矩形保持编辑状态时，部分观察升到 40–50 秒，退出草图拉伸后
回落到约 2–5 秒。当前仅定位到读回环节，不将猜测写成某个底层 API 的确定缺陷。
只读进程核对未发现另一套 Python 助手在争用该会话；这也不能排除 SolidWorks 内部插件等因素。

按当前脚本源码计数，12 格全部包含保存重开需要 455 次宿主 RPC，其中 287 次显式
`model.observe`，还不包含候选/检查点内部观察。1800 秒整批预算并没有足够实测依据保证覆盖全套。
本轮已补写入前剩余预算检查；后续仍需逐读回环节耗时剖析及同一受控会话分批，
才能合理提高覆盖。不能通过删除几何验证、盲目加大重试次数或跳过保存重开
来获得好看的完成率。也不能重启脚本后绕过非空现场保护接管上一进程的未知文档。

后续优先顺序：

1. 剖析草图几何读取、类型转换和原生引用读取的真实耗时，不凭单次慢读猜测根因。
2. 在已有预算准入上增加安全分批，优先取得前/上/右平面的可比数据。
3. 完成真实自主任务证据采集器（含圆柱/贯通孔的独立几何证明），再执行 10×3 基准。
4. 在这些门禁通过前，不继续扩大不受验证的建模能力或宣称复杂零件已可靠完成。
