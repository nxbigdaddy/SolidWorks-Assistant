# 本地模型库设计

## 1. 两阶段处理

快速扫描递归发现 SolidWorks 文件并记录规范路径、类型、大小、修改时间、快速指纹和状态，完全
不启动 SolidWorks。发现阶段每 100 个文件报告一次活动，随后进入确定进度的索引阶段。深度读取才
通过 COM 获取配置、文档与配置属性、材料、方程、尺寸、特征、质量属性、几何摘要、装配引用以及
工程图页/视图。Manifest 当前为 schema 2；COM 不提供或文件不具备的字段保留为空值。
质量使用 SolidWorks MassProperty 读取；未分配材料或无法计算时 `mass_available=false`，不能把
`mass_kg=0` 当作已知真实质量。

## 2. 哈希

- `file_sha256`：完整文件内容哈希，用于写任务前的源版本校验。
- `quick_fingerprint`：文件头尾分块加元数据，用于大批量增量发现。
- `manifest_sha256`：规范 JSON 的参数哈希，用于参数快照去重。

哈希不能代替几何等价验证。相同 Manifest 只说明已读取参数一致。

## 3. 扫描任务

任务报告阶段、总数、当前序号、当前文件、成功、失败、跳过和耗时。停止是合作式取消；已经
写入的记录保留。只有完整完成目录遍历时才允许把未发现记录标记为缺失。

深度读取前重新计算完整文件 SHA-256；只有完整哈希、参数哈希和参数状态均表明未变化时，才直接
跳过 SolidWorks，同时刷新大小、修改时间和快速指纹。实际参数读取前后再次比较完整 SHA-256；若文件
在读取期间发生变化，则不保存参数快照并提示重试。

## 4. 派生策略

- 原样复制：零件字节复制；装配体使用 Pack and Go。
- 参数派生：只修改 Manifest 中确认可写的驱动参数。
- 重绘：仅当能力报告中的所有必要特征都受支持。
- 混合：先复制，再重建局部受支持结构。

所有策略先产生数据型 `DerivationPlan`，核对源哈希、目标冲突和参数控制权后才执行。

当前版本已实现零件原样复制、零件参数派生和装配体 Pack and Go。参数派生先在目标目录创建唯一临时副本，只修改副本，
重建、保存、重新打开并核对目标尺寸后，以不覆盖方式发布。执行前后都核对源 SHA-256。普通文件复制
无法保证装配引用完整，因此装配体通过官方 Pack and Go API 复制引用关系、工程图普通复制仍会被明确
拒绝。Pack and Go 先写唯一临时目录，检查非空文件、装配体入口、源哈希与 API 状态后才原子发布；目标
目录已存在时绝不覆盖。该 COM 适配器仍需在目标 SolidWorks 版本上做真实装配体矩阵回归。

## 5. Document Manager

架构预留 Document Manager 读取器，可在拥有有效许可证密钥时不启动完整 SolidWorks 读取属性、
配置和引用。完整特征、实时重建与几何验证仍走 COM 通道。

## 6. 参数分析

分析只读取最近保存的 Manifest，不启动 SolidWorks：

- 快照差异按尺寸、文档/配置属性、特征序列、材料和几何摘要分组。
- 依赖图解析装配组件和工程图视图引用，并标记未入库或磁盘缺失目标。
- 质量报告检查非零特征错误码、空/缺失/重复引用、压缩组件和不可用质量属性。
- 相似度按特征类型、尺寸名称、属性字段和材料加权；它用于候选排序，不证明几何等价。
