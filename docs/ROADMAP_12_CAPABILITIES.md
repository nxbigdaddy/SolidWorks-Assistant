# 12 项能力迭代规格与验收路线

## 1. 目标与边界

本轮在 v3.0.0 Event Bridge 基线上同时推进 12 项能力。所有写模型动作继续由 Python STA COM Worker 串行执行；C# Add-in 负责 SolidWorks 内嵌入口、应用/文档事件和只读上下文采集。模型只生成结构化建议，工具白名单、能力门控、状态机、后验验证和人工确认仍拥有最终控制权。

依赖许可证、SolidWorks 版本或企业环境的能力，必须提供可测试协议、Fake 适配器、显式能力门控和真实环境验收脚本。未取得真实许可证或夹具时，不得把协议测试描述为实机通过。

## 2. 统一工作流

```text
用户 / SolidWorks Task Pane
  -> ContextSnapshot（文档、选择、配置、命令状态、能力）
  -> Intent / WorkflowSpec
  -> Preflight（版本、许可证、输入、目标、风险）
  -> PersistentJob + JobItems
  -> 单步执行 -> Fresh Snapshot -> Verifier
  -> 成功继续 / 暂停恢复 / 人工接管 / 安全终止
  -> Audit + Evidence + Capability Run
```

所有长任务采用同一持久状态：`queued/running/paused/waiting_user/succeeded/failed/cancelled`。停止是协作式取消；正在 SolidWorks 内部执行的原子 COM 调用不能强制回滚，但返回后不得再开始下一项。

## 4. 核心数据对象

### 4.1 ContextSnapshot

- `captured_at`、`source_session_id`、`sequence`、`stale_after_ms`
- SolidWorks 版本、进程、命令进行状态
- 活动文档路径、标题、类型、配置、保存状态、更新戳
- 选择数量、对象类型、名称、组件路径、持久引用摘要
- 当前可用能力及证据

快照不得保存 COM 对象。超过过期时间、进程序号变化或文档更新戳变化后必须重新采集。

### 4.2 DiagnosticIssue

- 稳定规则 ID、严重度、范围、对象引用、证据
- 用户可读说明、建议动作、是否可自动修复
- 自动修复前置条件和修复后的验证器

### 4.3 PersistentJob

- 工作流类型、输入摘要、状态、进度、取消请求
- 执行租约、心跳、尝试次数、错误分类
- JobItem 的幂等键、输入、输出、证据与审计时间

### 4.4 DemonstrationRecipe

- 来源会话、适用文档类型、上下文约束
- 命令序列、每步前后差异、目标解析策略
- 风险等级、审阅状态、回放次数、成功/失败统计

## 5. 数据库演进

模型库数据库从 schema 2 单向迁移到 schema 3：

- 扩展 `jobs`：租约、取消、输入/输出 JSON、错误和恢复时间；
- 新增 `job_items`：顺序、幂等键、状态、尝试、输入、输出和错误；
- 新增 `semantic_documents`：规范化搜索文本、字段令牌和索引版本；
- 新增 `demonstration_sessions`、`demonstration_actions`、`recipes`；
- 新增 `capability_runs`：版本、能力、证据、结果和环境标签。

迁移必须处于单一事务；遇到未知更高版本拒绝启动。已有 manifest schema 2 不在本轮无必要升级。

## 6. 能力门控

每个适配器返回 `available/unavailable/unknown`、原因、来源、版本和时间。以下情况必须显示“不可用”，而不是执行后再猜测：

- Document Manager/PDM/DimXpert 许可证缺失；
- 当前文档类型不匹配；
- Interop 中没有目标成员；
- 目标 SolidWorks 主版本未完成真实夹具验收；
- 文档只读、正在执行命令或上下文已过期；
- 输出路径冲突或源文件哈希已经变化。

## 7. 测试层级

1. 纯单元测试：状态机、规则、迁移、搜索、配方、能力门控。
2. Fake 适配器契约测试：装配体、工程图、PMI、PDM、产品族。
3. C# 自测：事件传输、文档宿主生命周期、上下文序列化、Task Pane 契约。
4. 进程测试：Worker 中断、批任务租约和崩溃恢复。
5. 本机 SolidWorks 冒烟：只读能力探测、事件、上下文、一个临时零件/装配体/工程图。
6. 多版本实验室：每个版本保留机器、Service Pack、Interop、模板、语言和证据文件。

## 8. 交付顺序

1. 封存基线并建立本文档。
2. schema 3、统一能力/上下文/诊断/任务模型与单元测试。
3. Add-in 文档事件宿主和 Task Pane；Python 实时上下文消费。
4. 健康诊断、产品族、持久任务、语义搜索。
5. 装配体、工程图、人工操作学习。
6. PMI/DFM、PDM/Document Manager、多版本实验室。
7. UI 收口、全量自动化、本机夹具、发布文档与版本包。

## 9. 完成定义

“完成”表示：代码、迁移、UI 或可调用入口、取消/恢复、审计、Fake 契约测试和文档均已交付；在当前机器具备的 SolidWorks/许可证条件下完成真实验证。外部许可证或未安装版本导致的未验收项必须列入能力实验室报告，不能静默降级或声称通过。
