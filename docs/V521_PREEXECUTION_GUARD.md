# 5.2.1：写前状态检查修正

日期：2026-09-07。分支：`codex/v5.2.1-write-preconditions`。
回退基线：`v5.2.0-baseline` / `6146dd5`。本轮不构建 EXE，不操作或重启 SolidWorks。

## 本次实际问题

本地最新会话 `session-20260907-131933-498869.jsonl` 记录：

- 13:26:09，严格观察为试验副本，活动草图为空草图；随后发出矩形命令。
- 13:26:12，worker 的操作前快照却为原零件，未编辑草图。
- 13:26:18，操作后快照回到副本，草图内已有四条矩形边和两条构造线。
- 13:26:37，运行器事后比对失败，报 `StateChanged` 并暂停；13:39:41 任务被停止。

因此这次不是找不到基准面，也不是矩形 API 不支持：矩形实际已画入副本。
确定的软件缺口是 worker 没有在执行前核对该快照是否仍符合宿主已确认的状态，导致检查发现得太晚。

只读检查未发现本程序后台刷新主动切换文档的代码路径，也没有证明 COM 缓存失效。事件桥没有这次切换的有效记录。
人工切换、外部程序或 SolidWorks 瞬态行为，现有证据无法区分；不得归咎于用户或模型质量。

## 修正

1. 连续任务的已有文档建模动作使用 `SolidWorksWorkerClient.call_checked`；bootstrap 会话连接和新建文档仍走原入口。
2. 预期观察放在私有 RPC `expected` 中，独立于模型可填写的 ToolCall 参数；客户端复制该数据，避免提交后被改写。
3. 在同一个 CAD 串行门内，采集操作前快照，核对预期关键字段、原生文档身份及可用的配置/更新戳，再进入 `gateway.execute`。
4. 前置拒绝记录 `execution.started=false` 和差异字段；界面说明本次命令未执行，不要求为此撤销。真正进入执行后的异常不能冒充未执行。
5. 既有执行后快照、严格观察、特征与最终几何验收继续保留。停止发生在等待调用锁或收到晚到成功时，均不得重新启动或采纳旧调用。

这不是取消状态检查，也不是在文档不确定时强行自动重试；本轮不自动接管旧任务或激活任何候选文档。

## 边界与后续

- 本轮没有真实 CAD 编辑、外部模型请求或新 EXE/安装器测试。模拟原生对象的生产代码路径测试，不等于实机全链路验收。
- 本次切换的原始触发源仍待确认；应补充活动文档切换事件的关联记录，并在隔离测试文档中执行生产进程 RPC 实测。
- 快照仍含既有 best-effort 读取，写前核对不是跨所有外部 COM 客户端的原子事务锁；保持未知证据拒绝与事后独立验收。
- 只修复“先执行、后发现前提已不一致”的缺口，不宣称所有暂停都已解决；性能优化、Pi 原生建模工具与多阶段检查点分支仍是后续工作。
