# 旧版迁移方案

## 1. 归档边界

重构前项目完整位于 `old/`。新代码不得把 `old` 加入 `PYTHONPATH`，也不得导入旧模块。归档的目的仅是
回退、需求核对和一次性数据迁移。

## 2. 数据来源

可能需要迁移的内容包括旧模型服务设置、模型库索引、参数 Manifest、标签和历史需求。日志、测试缓存、
构建目录和发布包不迁移。

## 3. 迁移步骤

1. 在用户数据目录创建新数据库备份。
2. 只读打开旧 SQLite/JSON，识别 schema 和记录数量。
3. 规范化路径、文档类型和 JSON；不解密后重新保存不可读 DPAPI Key。
4. 分批写入新表并记录来源 ID。
5. 比较记录数、随机样本和哈希；完成后生成报告。

从源码目录启动时，程序发现根目录 `old/` 后会在界面显示后后台执行一次迁移，并在用户数据目录写入
`legacy-migration-v3.json`。导入使用稳定的 `legacy-<id>` 历史 ID和 SQLite `INSERT OR IGNORE`，
即使人工删除完成标记后重跑也不会复制历史记录。迁移结果显示在“活动与审计”。

## 4. 凭据

旧 DPAPI Key 只有成功解密时才可用新格式重新加密。解密失败时保留地址和模型，但新配置明确标记为
“需要重新输入”，绝不能用空 Key 发起认证请求。

当前导入器不尝试解密或复制旧密文。它迁移地址与模型名，创建
`legacy-credential-reentry-required` 标记；规划器在用户重新保存设置前拒绝发送模型请求。

## 5. 回退

迁移不修改旧数据库。失败时删除尚未投入使用的新数据库并从自动备份恢复；旧程序仍可从 `old/` 手工
启动，但不能与新程序同时写同一数据文件。
