# 5.3 可靠执行与交互建模

## 本轮目的

解决的不是某一个圆、矩形或基准面，而是让任务形成可核查的闭环：提出阶段、执行前核对、
隔离试验、读取真实结果、保存可恢复的进度，再决定下一步。程序保持现有界面和功能模块，
不把重新生成代码、提高重试次数或换模型当作根治方案。

旧源码基线为 `v5.2.1-baseline`（`b6493ac`），本轮开发分支为 `codex/v5.3-reliability-core`。
开发目录仍为 `SolidWorks-Assistant`；不是启动旧目录 `solidworks_tools` 下的程序。

## 执行权如何分配

| 层次 | 负责内容 | 不能做的事 |
| --- | --- | --- |
| Pi 会话 | 读取受控调查结果，提出并调用一个建模阶段，根据回执继续调整 | 不获得 Shell、任意文件、DLL、COM 或任意 API 权限 |
| 宿主任务运行器 | 校验工具白名单、参数、锁定目标、执行预算、取消代次；决定是否允许执行 | 不把模型声称成功当成几何验收 |
| 独立 CAD 工作进程 | 串行执行、核对文档/配置/状态、操作原生对象、返回观察与错误 | 不因当前活动文档变化而重定向写入，不自动重放未知结果 |
| 检查点存储 | 独立原生文件、SHA256、证据 manifest、任务与父检查点关系 | 不保存模型提供的任意路径，不把任务 JSON 当作 CAD 文件 |
| 用户界面 | 公开进度、停止、人工反馈、显式恢复 | 不显示模型隐藏推理，不在点击恢复记录后自动建模 |

原有 C# Event Bridge 继续作为可选事件桥接。本轮没有将执行器重写成 C# Add-in；其价值需要
单独评估。Add-in 也不能消除原生几何失败，或自动提供数据库式事务。可靠性首先来自统一
执行边界、证据和恢复协议，而不是语言或进程位置。

## 生产执行改动

1. `checked_call` 在同一串行执行门内验证预期快照、原生文档身份、配置与更新戳。
2. 验证后绑定一个文档对象。后续帮助方法使用该对象；如果活动文档偏离绑定对象，拒绝把操作
   转移到另一个模型。这不是对外部 UI/COM 的全局锁，外部编辑仍可能导致暂停。
3. 前置拒绝与执行中失败分开：`execution.started=false` 才表示没有进入执行；已进入但发生
   异常的结果不能当作“没有修改”，不自动重放或按猜测撤销。
4. `model.observe` 本身是严格读取，取消包围它的两次额外宽泛快照。其他写前/写后核对不删除。
5. RPC 显示等待通道、检查前置状态、执行、读取结果、保存/恢复检查点及耗时。
   只有固定阶段与耗时元数据，不传递命令参数或原始模型文本作为进度。
6. 普通 RPC 默认 120 秒；候选创建 180 秒、结束 240 秒；检查点列举 120 秒、恢复 240 秒。
   等待本地调用锁计入固定期限；心跳不延长期限。取消后禁止旧调用重启新工作进程。

## 持久检查点

只有候选阶段通过局部几何验收，才保存当前最终内存状态为新的原生 `.sldprt` 检查点。
候选初始种子文件与最终检查点是两个文件，不能混用。

保存流程核对保存前后的文档、配置、更新戳、原生几何，计算原生文件 SHA256 与大小，原子发布
manifest。文件哈希用于损坏检测，不是抵御恶意本地管理员的数字签名。保存失败不采用该阶段；
部分写出的文件保留但不会冒充已验收检查点。

检查点使用短而可区分的原生文件名，完整任务 hash 和检查点 ID 仍保留在目录及 manifest 中。
保存/打开前检查 UTF-16 路径长度；Windows 长路径支持不代表 SolidWorks 保存 API 同样支持。
结束回执中的具体错误码、原因和验证差异进入任务记录，不再只显示泛化的“比对失败”。

恢复是单独的用户动作：选择已记录检查点，复制成一个新的恢复工作文件，打开后独立读取原生
几何，与保存证据比对，验证成功后才绑定任务。检查点原文件不被打开用于修改，不关闭或删除
任何已有文档。恢复完成停在“就绪”，不会自动继续建模。
读取任务记录、检查点列表及显式恢复不需要模型配置；真正继续建模时才校验模型配置，补齐设置
不会为此重启 CAD 工作进程或丢失刚恢复的文档所有权。

允许恢复的现场仅为：无活动文档，或同一工作进程已验证且未变化的当前任务文档。对于重启后
遗留的未知活动文档，不通过文件名或旧 token 接管；需用户先处理现场，再显式恢复。原生工作
进程仍有未完成候选时也拒绝恢复。旧任务 JSON 可以保留未完成试验记录，但它不构成 CAD 权限。

恢复成功前缀和相应证据，但不回滚用户后续补充的目标、限制、历史失败、预算和消息。旧实体
引用与未执行步骤失效；后续必须重新观察和规划。父检查点关系支持从旧检查点继续形成分支，
本轮没有实现多分支自动并行搜索或可视化分支树。

首期范围是几何可完整验证的单配置、无外部引用零件；不承诺任意装配体、3D 草图和所有复杂
拓扑都可恢复。原生保存成功与源状态不变是保存证据；恢复时另做文件重新打开后的几何验证。

## Pi 原生阶段工具

`sw_model_stage(decision_json)` 不是“执行任意代码”，而是让 Pi 在同一会话调用宿主受控的
TaskDecision 阶段。工具结果回到 Pi 后，它可以据此改变参数或构造路线。原有返回阶段提案的
方式继续兼容；Pydantic 后端保留提案模式，不从异步线程绕过 CAD 执行边界。

- 仅真实 `run` 范围、同执行线程允许调用。“仅准备”绝不因此获得写权限。
- 每次决策最多两个原生阶段尝试，单阶段模式最多一个；无效/拒绝尝试也计入额度。
- 原有全任务动作预算、白名单、隔离候选和锁定目标继续生效。
- request_id 与内容摘要防止同一请求重放；更改同 ID 内容、旧取消代次请求和结果未知的重试均拒绝。
- 一个阶段执行看门狗 600 秒，Pi 桥接等待上限 630 秒。CAD 回调耗时与模型响应空闲时间分开，
  但仍有硬期限，不能靠心跳无限运行。
- 已经原生执行的阶段，不再从同轮最终 `act` 提案重复执行。执行开始后发生通信错误，不切换
  另一个模型盲目重放。

## 验收方法

自动回归和真实 SolidWorks 验收是不同证据。`scripts/verify.ps1` 是本地源码与模拟边界测试，
不会编辑真实 CAD。新 `scripts/live_production_reliability_smoke.py` 才通过生产的
`ContinuousTaskRunner → SolidWorksWorkerClient → spawn → worker_main` 进行实测。

实机脚本使用固定本地后端，故不能证明真实模型已能自主完成复杂任务。它要求显式 `--execute`；
需要启动 SolidWorks 时还要 `--start-solidworks`。开始时有任何已打开文档就拒绝，不自动关闭
它们；不发送真实图纸、日志或凭据至外部模型，所有测试文件保留。

本轮具体命令、数量、耗时、失败与最终结论见 `V530_VALIDATION.md`，不得用旧版验证替代。

## 仍需持续迭代

本轮新交互建模和检查点闭环作用于默认持续任务入口。兼容固定计划、模型库等功能保留已有
流程，虽然共享同一 worker 和取消通道，但没有整体改为 Pi 原生阶段/持久检查点工作流；
兼容固定计划尚未全面迁移到 `checked_call`。不能把当前持续任务验收扩大成所有旧入口的同等保证。

不能承诺“永不失败”。成功标准是：可恢复几何失败能基于新证据调整；无法确认是否写入、外部
文档变化或权限不足时可靠停止，并提供可验证的恢复途径。任意复杂零件自动建模、开放式 API
编程、自动跨分支择优、跨版本 SolidWorks 能力矩阵和 C# 执行核心仍需专门开发与验收。
