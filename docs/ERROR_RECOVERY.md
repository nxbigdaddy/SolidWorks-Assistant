# 错误目录与恢复

## 1. 规划错误

认证失败、限流、服务端错误、响应过大、JSON 无效、工具未知和参数越界都不会载入执行器。界面保留原始
需求，显示请求阶段与可操作错误；停止后迟到响应通过请求号失效。应用只展示阶段和结果，不展示模型
内部思维链。

## 2. SolidWorks 错误

| 现象 | 判断 | 首选恢复 |
| --- | --- | --- |
| 找不到基准面 | 多语言名称和序号回退均失败 | 检查文档类型/特征树，人工选面后验证或改面 |
| API 返回但快照不变 | 后验条件失败 | 检查选择状态，修改参数或人工完成后验证 |
| COM 超时/进程退出 | 工作进程失联 | 停止、检查模型状态、重新连接后从失败步恢复 |
| 拉伸失败 | 草图未闭合、方向或特征条件不成立 | 编辑参数，或让模型替换失败后缀 |
| 正多边形中途失败 | 旧实现逐边创建造成残留线段 | 优先使用原生 `CreatePolygon`；兼容回退失败时删除/撤销本次新增线段 |
| 右视基准面位置错误 | 草图局部坐标与世界坐标混用 | 使用 `right: local(x,y) -> world(Y,Z)` 转换并在后验中核对三维点 |
| 原点附近的小几何未创建 | SolidWorks 自动关系推断拒绝了有效精确坐标 | 自动切换 `AddToDB` 精确创建并复核实体数 |
| 文件读取失败 | 缺失、锁定、引用或版本问题 | 单文件记失败，批次继续；修复文件后重读 |

完全相同的工具、参数、错误码和消息只允许原样重试一次。重复失败必须改变环境或计划。
若删除失败步骤后剩余计划不再满足草图、闭合轮廓、实体或切除依赖，执行器拒绝“跳过”，要求修改参数、
人工完成并验证，或由模型替换失败后缀。

## 2.1 自动恢复策略

每个失败现在会生成结构化恢复判断：`category`、`fingerprint`、`model_changed`、`state_known`、
`safe_retry`、`ai_repair_recommended`、`manual_review_required` 和可解释原因。

- 暂时性错误且前后快照一致：自动进行一次受控重试；
- 几何、拓扑、能力或未知错误且快照可证明模型未变化：自动把脱敏故障包交给已配置的模型服务；
- 模型已经变化或失败后状态未知：禁止自动重试和 AI 后缀替换，保留现场要求回滚/人工检查；
- 自动模型修复每个计划最多两次；历史失败步骤、参数和失败指纹会进入下一次修复上下文，禁止返回相同失败方案；
- 用户选择“执行全部”且开启“修复后自动继续”时，替代后缀必须先通过本地工具、参数和语义校验，随后才继续执行。

发送给模型的上下文会去除本地路径，只包含原需求、成功前缀、失败步骤、错误分类、前后模型快照、
历史失败方案、坐标约定和可用工具名称，不发送本地 traceback。

## 3. 派生错误

目标已存在、扩展名不符、源在处理中变化、尺寸不可写、读回不一致、重建/保存失败或重开验证失败都会
取消发布并清理临时文件。源文件仅被读取，并用执行前后 SHA-256 证明未变化。装配体普通复制被安全
拒绝，不允许生成引用不完整的“成功”结果。
零件复制、哈希和参数派生均分块检查“停止全部”信号；取消后未完成目标与临时副本会被清理。

## 4. 凭据错误

DPAPI 密文无法由当前 Windows 用户解密时，设置仍保留在原文件中，但运行配置标记为不可读；模型请求
被阻止，用户必须重新输入或明确清除。旧版迁移从不复制密文。

## 5. 诊断证据

界面活动日志用于即时查看；用户数据目录中的 JSONL 是追加式审计记录；`history.db` 保存任务摘要；
`library.db` 保存文件事件和参数快照。日志脱敏匹配 Key、Token、Authorization、Secret 和 Password，
但模型路径与需求可能仍属敏感工程信息，提交外部支持前应人工检查。
