产品价值从“会画”到“画得稳”

它解决的，不只是“自动画一个模型”

CAD 自动化真正困难的地方，是选择对象会变化、操作有先后关系、失败后还要知道停在哪里。助手把这些问题放进同一条可观察的工作流。

操作介绍第一条路线：自然语言建模

先生成计划，再让 SolidWorks 动手

以“新建一个直径 40 mm、高 30 mm 的圆柱零件”为例，普通用户只需要表达目标；系统负责把目标拆成受控步骤。

1
描述目标

写清楚对象、关键尺寸和希望得到的结果。

2
生成并校验

系统检查工具是否允许、参数是否合理、先后顺序是否成立。

3
查看预览

确认草图轮廓、拉伸方向、步骤数量和说明。

4
逐步执行

建议首次使用“执行下一步”，复杂操作始终保留人工观察。

5
核对结果

系统读取模型状态；用户再决定保存、继续派生或结束任务。

输入建议

优先写明确尺寸和基准，例如“前视基准面”“盲孔深度 12 mm”。

确认重点

关注选择对象、尺寸单位、凸台/切除方向和预期实体数量。

复杂任务

拆成多个可验证阶段，比一次性生成很长的命令序列更可靠。

交互式执行每一步都建立新证据

不是“发完命令就相信成功”，而是执行后重新检查

SolidWorks 操作依赖前序特征、选中对象和模型拓扑。系统通过前后快照与后验条件，确认当前步骤是否真的改变了模型。

读取现场文档、配置、选择
→
执行一步调用白名单工具
→
重新读取刷新模型快照
→
检查结果实体、特征、尺寸
→
继续 / 暂停由证据决定
选择更稳定

命名目标与持久引用

把“刚才选中的面”转成可恢复的目标引用，拓扑变化后如果失效会明确提示，不盲猜。

状态更可信

新鲜快照

每步前后都从 SolidWorks 读取当前状态，避免使用已经过期的选择或缓存。

操作可控

统一停止

停止会阻止后续步骤并终止助手工作进程；已被 SolidWorks 接收的原子调用仍需事后核对。

适合的节奏

简单重复任务可以连续执行；新模型、复杂装配或不熟悉的特征，建议保持“执行一步—检查一步”。

06 / 20
失败恢复停在问题处，不丢失成功前缀

遇到问题时，用户仍然掌握下一步

  1. 1
    调整环境后重试修正 SolidWorks 当前选择、活动文档或草图状态。
  2. 2
    编辑参数并重试修改尺寸、方向、目标面等当前步骤参数。
  3. 3
    人工完成后验证用户在 SolidWorks 中完成操作，系统重新检查结果。
  4. 4
    让模型修复后续计划保留成功步骤，把失败信息交给规划器重新安排后续。
  5. 5
    跳过仅在明确知道该步骤不影响后续时使用，并保留审计记录。

操作介绍第二条路线：模型库扫描

先快后深：大目录也能逐步建立参数库

扫描分成两层，避免为了列出文件就启动 SolidWorks。只有需要特征、尺寸、配置或引用关系时，才进入深度读取。

快速扫描 无需启动 SolidWorks

  • 发现 SLDPRT、SLDASM、SLDDRW
  • 记录路径、类型、大小和修改时间
  • 生成快速指纹，识别未变化文件
  • 适合第一次建立索引或日常增量刷新

深度读取 需要 COM 或合法 DM 许可

  • 读取配置、属性、材料、特征和尺寸
  • 读取装配引用、工程图视图和几何摘要
  • 生成完整文件哈希与参数 Manifest
  • 支持取消；失败文件单独记录，不阻塞全目录
快速指纹用于判断“这个文件是否可能变化”，减少重复深读。
文件 SHA-256像文件的数字指纹，用于确认源文件是否保持不变。
参数 Manifest 哈希确认配置、尺寸、材料等结构化参数快照是否变化。

什么时候必须打开 SolidWorks？ 快速扫描不需要；当前深度读取通常由独立 SolidWorks COM 工作进程完成。配置合法的 Document Manager 许可证后，可在部分元数据场景减少界面启动，但不能替代全部几何和特征验证。

模型复用复制、派生、重建各有边界

根据目标选择正确的复用方式

系统不会把所有文件都当成同一种“复制”。零件、装配体、工程图的引用关系不同，安全路线也不同。

方式适合场景系统如何保护结果当前状态
原样复制零件保留结构与参数，生成独立文件不覆盖目标；复制前后核对哈希已实现
参数派生零件修改指定尺寸或属性，形成新规格先复制到临时区，只改副本；重建、保存、重开再发布已实现
产品族同一设计生成多个配置和规格组合以配置矩阵驱动，稳定尺寸身份和属性映射已实现
Pack and Go装配体连同所有引用一起发布调用 SolidWorks 官方 API，临时目录验证后原子发布已实现
安全格式导出STEP、STL、IGES、PDF、DXF、DWG 等交付格式白名单、不覆盖、检查非空输出和哈希已实现
复杂零件重绘需要理解圆角、曲面、放样、孔向导等完整设计意图当前仅开放基础草图、拉伸和旋转；不支持时明确拒绝受限
最重要的规则

源文件默认保持不变；装配体不做普通文件复制，必须使用 Pack and Go 保留引用完整性。

技术亮点用工程约束提升可靠性

六项设计，让 AI 辅助更接近工程软件

1

结构化计划

模型只能选择已登记工具并提交明确参数，不能随意执行命令字符串。

2

后验验证

执行后读取实体、特征、尺寸和文档状态，用结果判断成功。

3

COM 进程隔离

SolidWorks 调用在独立进程中串行执行，停止和故障不会锁死整个界面。

4

持久引用

对关键面、边和基准保存可恢复引用；失效时显式报错，不猜测替代对象。

5

幂等任务

批处理为每个任务项保留唯一键、租约和心跳，减少重复执行。

6

证据化发布

复制、派生、导出先在临时区完成，检查文件、哈希和重开结果后再发布。

简单理解

AI 像“提出步骤的工程助理”，本地规则像“工艺审核员”，SolidWorks 的实际结果才是最终验收依据。

安全与隐私本地优先，写操作受控

保护源文件，也保护操作决定权

本地数据与工程文件
保持在用户控制范围内凭据、哈希、审计、临时发布共同防护

凭据保护

模型服务 API Key 使用 Windows DPAPI 按当前用户加密；日志不记录明文密钥。

源文件保护

派生修改副本，装配使用 Pack and Go；目标已存在时默认拒绝覆盖。

人工控制

高风险动作保留确认和单步入口；失败后由用户选择恢复路线。

能力门控

没有许可证、COM 组件或版本证据时显示不可用，不伪装成已成功。

可审计记录

计划、任务、结果和恢复决策写入本地记录，方便定位问题。

明确边界

系统不是 PDM，也不是无人监管的通用宏执行器；复杂未知特征不会盲目生成。

应用场景从个人提效到团队资产沉淀

哪些工作最适合先交给助手

优先选择规则清楚、结果可检查、重复频率高的场景；复杂创新设计仍以工程师判断为主。

A01基础零件与标准结构快速建模明确草图、尺寸、拉伸或旋转目标，适合单步验证。
A02同类零件参数化派生从可靠源模型生成不同规格，保留源文件并验证新文件。
A03本地模型盘点与查找快速建立索引，再按需提取参数、引用和健康信息。
A04装配检查和工程图准备识别缺件与干涉，生成标准视图、BOM、气泡和交付格式。
A05批量质量检查与索引维护将重复任务排队运行，中途暂停，程序恢复后继续。
A06标准作业引导和经验沉淀记录人工操作，审阅后作为配方逐步引导新用户。
选型原则

任务越能清楚描述“输入、步骤、预期结果”，越适合自动化；越依赖隐含设计意图，越需要人工主导。

快速上手第一次使用建议路线

五步完成安装、连接和第一次任务

安装程序

在 Windows 电脑安装桌面端；如需 SolidWorks 内嵌入口，再注册 C# Add-in。

配置模型服务

在设置中选择服务商、地址、模型和 API Key；凭据按当前 Windows 用户加密。

确认 SolidWorks

启动受支持版本，检查右侧实时上下文是否显示活动文档和能力状态。

建立本地索引

先做快速扫描；选择少量代表文件进行深度读取，确认参数结果。

从单步开始

输入简单任务，检查计划和预览，逐步执行并观察 SolidWorks 模型变化。

基础环境

Windows 10/11、SolidWorks、可用模型服务；开发环境要求 Python 3.11+。

首次验收

建议使用副本或专用夹具，核对停止、恢复、重开验证和目标目录保护。

迁移到新电脑

重新输入 API Key；DPAPI 加密内容不能直接跨 Windows 用户解密。模型库可重新扫描建立。

推荐试运行：先完成“快速扫描一个测试目录”和“逐步生成一个简单圆柱”两条路线，再启用产品族、装配体、工程图和批处理。

对工程师保留参数、选择、结果和失败证据，减少黑盒式自动化。
对团队把模型、参数、标准操作和批任务沉淀为可持续管理的本地资产。
对管理者以明确验证范围和技术边界评估落地，不用模糊的“全自动”承诺。
