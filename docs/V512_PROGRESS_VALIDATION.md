## 本轮问题和证据

用户报告“又没有进展”，本轮不再仅依赖模拟测试，而是读取最新本地记录、核对真实 GUI，
调用当前配置模型进行合成任务对照，并执行真实 SolidWorks 未保存夹具。

最新失败任务停留在第 1 轮、0 个已执行动作：Pi 一共返回 404 次 assistant 响应，产生
405 次工具调用，其中实际调查 8 次、错误地请求 `session.ensure` 1 次、额度拒绝 396 次。
超过额度后，工具依然暴露给模型，错误结果又标记为成功；模型继续工具调用刷新响应空闲计时。
宿主只收到最初 8 次调查，故外层无进展计数无法约束内层。最终 900 秒整轮硬限才转人工检查。

这是 Agent 编排问题，尚未进入 CAD，不是基准面选择或 SolidWorks 建模 API 的失败。
此外，真实圆修复测试暴露了第二个独立问题：`ISketch` 并没有代码原来假设的 `GetFeature`。
此前使用有该方法的 fake COM 能通过，但真实 SolidWorks 2025 返回 `<unknown>.GetFeature`。
继续真测又定位到圆心校验失败：通用 `_read_member` 在动态 COM 返回对象时直接取属性，
`CreatePoint` 的实参被丢弃，得到默认零点。仅改为双精度 SAFEARRAY 仍失败；最终对两个固定
数学方法显式使用 `IDispatch.Invoke(DISPATCH_METHOD)`，并在变换前后独立回读验证，才实际通过。

后续全链路又定位到第三个独立问题：CAD 已执行完 6 个步骤，但 Pi 最后响应
`stopReason=length`，输出额度恰好 8192，仅包含内部推理而没有公开阶段决策。
原代码将“没有返回可用决策”归为 Pi 不可用，因而停止。这里是响应被截断，不是服务断线；
不能把内部推理内容当作执行命令，也不能通过重复建模步骤补救。

再一轮真实复测暴露第四个提前终止路径：跨轮累计六次无新证据调查后，运行器立即转人工检查。
该轮 Pi 实际已经自行补齐 `document.new_part`，随后返回完整正确的 6 步方案与 X/Y/Z 外廓目标，
但因为任务已提前进入 review，正确提案被丢弃。无效调查次数不能等同于失败策略次数；
此处应结束调查并要求决策，而不是抢先结束整个任务。

## 修正原则

- 原生 Pi 每轮最多 8 次宿主调查，最多 10 次全部工具尝试；后者包括无效参数和未知工具。
- 达到额度后真实撤去工具，而不只是返回“次数已用完”。模型下一次请求只应提交阶段决策。
- 工具错误标为错误；如果撤工具后仍调用工具，立即结束本次候选并交给外层有限纠错，
  不再等 15 分钟，也不自动换模型引擎。
- 最后的决策等待有独立时限；无效 `toolcall_delta` 不能刷新它。取消后不能重新开始 CAD。
- 下一个外层任务阶段恢复只读工具；原生 Pi 多次 tool turn 不会重置额度。
- 明确“未连接/没有文档”是未初始化状态。连接、新建文档属于 `act.steps`，不属于只读调查。
- 原生观察同步给后续诊断，但不把观察擅自提升为已验证的执行检查点。
- 真实草图所属特征通过特征树与 `GetSpecificFeature2` 反向查找，再核验 IUnknown 身份；
  不能仅凭同名特征授权修改，也不能省略实体所有权与修改后读回。
- 仅针对 `CreatePoint` / `MultiplyTransform` 使用固定方法调用，不泛化允许任意动态 COM 调用；
  双精度数组与回读是防线，不将数组类型误称为此次参数丢失的唯一根因。
- 运行中的公开响应/调查计数不再被旧快照覆盖；人工检查与结束状态仍优先显示实际结果。
- 初始化前已有文档的名称不得抢先绑定到本任务目标；新任务文档创建并核对后才绑定。
- 测试身份防护改用宿主私有轻量 RPC，不再每次额外遍历两次完整模型；未知身份拒绝，
  共享串行锁与取消代次，不注册成 Agent 工具，也不修改原有写操作前后快照规则。
- Pi 的长度截断归为可纠正的候选失败；保留成功前缀，在同一任务内有限续答，不当作引擎离线或
  自动回退依据。内部推理和截断 JSON 均不可执行。
- Pi 请求复用已有供应商兼容策略：仅官方 DeepSeek / DashScope 对应端点发送关闭默认推理字段；
  不根据模型名向任意代理添加字段。`--thinking off` 本身不代表服务端默认推理已经关闭。
- 增加受控只读外廓工具，使用 `IBody2.GetExtremePoint` 对最多 64 个实体做六方向测量，
  包括隐藏实体；核对文档、配置、实体身份，不使用近似包围盒回退。
- 最终外廓验收额外获取测量前后配置身份，缺失或变化则不能通过。普通 `model.observe` 不增加
  配置读取成本；宿主验收测量不消耗 Agent 每轮的 8 次调查配额。
- 独立尺寸目标不能复用同一命名参数，独立外廓目标不能复用同一轴。多个描述若确实指同一物理量，
  应引用同一个 goal_id；已绑定目标不能被静默放宽。
- 六次重复调查只触发本轮 `decision_only`，通过可信宿主信号撤去工具，继续接收正确提案。
  不再在原生模型尚未结束本轮时直接转 review；模型数据中的同名字段不能控制宿主。
  六次无效策略、总调查/轮次预算、取消和未知 CAD 状态的安全停止仍保留。

Agent 权限没有扩大到 Shell、文件写入、任意代码或直接 COM。CAD 写入仍是宿主校验的阶段提案，
不是与使用通用工具配置的独立 Pi 客户端完全等价。已核对本机 Pi 0.84.4 在相同 session ID
重启时会恢复已持久化历史；强制结束时尚未保存的流式内容不保证保留。

## 仍存在的速度瓶颈

对 `cube-1788713761052013000` 的 25 次工具调用进行只读分析：累计 461.154 秒，
其中 14 次 `model.observe` 用时 296.015 秒（64.19%）；外层私有身份检查共 20.779 秒（4.5%）。
一次写步骤目前包含 2 次严格观察和 6 次普通快照，重复遍历与质量属性读取较多。
该次矩形步骤合计 57.874 秒，拉伸步骤合计 97.468 秒。`operation_ms` 包括锁等待和 Worker
内部快照，不能直接当作原生 CAD 命令净耗时；以上统计也不包含外部模型等待。

本轮未为提速删除安全检查。下一轮适合先增加分段计时，再精简只读工具的重复快照，
最后设计宿主统一的单步执行/前后验证取证。必须继续核对文档、配置、停止代次、失败后的
部分修改状态，并统一可见实体与全部实体的统计口径；不使用按时间缓存几何或并行 COM。
