# 通用试验与恢复工作区：设计、实现与验收

日期：2026-09-07。状态：开发迭代，非安装包发布。当前基线：`v5.1.2-baseline` / `e1bb9d4`。

## 为什么改变方向

问题不是再补一个扳手操作，也不是简单增加 Pi 重试次数。此前 Pi 可以多轮调查，但建模程序缺少可安全替换的候选阶段；失败后若模型已经改变，执行器只能暂停。部分后置检查还把浮点体积噪声、错误合并当成成功，进一步污染后续决策。

本轮建立通用的“提出候选程序—在副本执行—独立检查—采用或返回基线—调整程序”的机制。不启用任意 Shell、文件读写、动态 Python、DLL 或模型直接 COM 权限。

## 为什么不用一次 Undo 作为恢复

SolidWorks 的 Undo 录制对象可能包含 API 之外的人工操作；`EditUndo2(1)` 没有任务专属令牌。调用返回不能证明恢复了草图、配置、选择、几何与原始引用。因此不以 Undo 数量证明恢复，也不自动撤销用户操作。

本轮使用原生副本隔离：原模型不写入候选几何；失败时只激活仍保持原状态的基线，重新验证。所有候选文件、文档均保留，取消时不偷偷切换、保存或关闭文档。

## 实现边界

1. `task_models.TrialSpec`：`hypothesis` 与可立即读回的 `checks`；`TaskDecision.act.steps` 是候选程序。最终锁定需求与目标不变。
2. `task_trials.TrialRunnerMixin`：候选历史、完整步骤检查、失败前缀剔除、自动返回基线、失败证据反馈、基于基线和程序的重复拦截。
3. `solidworks.checkpoints.CandidateWorkspaceMixin`：宿主工作目录、进程内新建文档所有权、原生复制、独立打开、身份/配置/更新戳/特征/草图/外廓检查、采用与返回。
4. `SolidWorksWorkerClient.candidate_request`：私有 RPC，与普通调用使用相同进程与串行门；路径不接受模型输入。停止令牌与晚到结果丢弃规则不变。
5. `tools.py`：凸台/切除真实材料变化方向、合并实体约束、缺测与非有限值拒绝、浮点噪声容差；人工文字确认不能代替实际参数读回。
6. `gateway.py`：多边形真实坐标与端点读回、命令返回实体的精确局部清理。局部草图清理不宣称整个文档恢复。

## 运行规则

- 正常启动的桌面程序启用候选工作区。初始化 `session.ensure` / `document.new_part` 单独执行；后续完整建模阶段必须提供 `trial`。
- 每个候选最多 12 个已有白名单步骤，不包含文档新建/切换；从稳定基准面开始，完成一个可独立检查的阶段。
- 局部检查必须包含几何指标，不能只检查文档类型、实体数和无错误；不能用局部检查删除或降低最终目标。
- 候选步骤暂存期间明确属于试验；只有全部步骤完成、局部检查与原生工作区复核均通过，才采用。
- 未通过的候选步骤、实体引用、目标临时绑定和虚假进展从有效历史中恢复；保留试验与失败审计。
- 相同基线上的同一失败程序不能靠改理由或降低局部检查重复尝试。真正改变参数/步骤才是新候选；连续无进展预算仍有效。
- 外部切换文档、配置或修改状态，权限拒绝、进程退出及无法读全的现场不能自动恢复。
- 停止后不发送 begin/finish/恢复/清理调用；未完成试验不能在重启后凭保存的 token 自动接管。

## 文件和模型保护

工作目录由宿主设为用户数据目录下 `candidate-workspace`，路径形如任务摘要/随机令牌/candidate-令牌.sldprt。模型不能选择路径。唯一目录创建、根目录校验和不覆盖检查保护既有文件。

仅本工作进程通过新建接口明确获得的新零件可登记；不能把 `ActiveDoc` 或“未保存”推断为本任务所有。接受的副本可以作为下一阶段基线，其他任务不能借用其所有权。

`SaveAs3` 使用 Silent + Copy + AvoidRebuildOnSave，不保存关联文档，不重命名原件；激活使用 DontRebuildActiveDoc。保存/打开错误和警告不当作成功。副本磁盘文件是候选初始状态；采用的是当前内存模型，不代表已保存最终 CAD 成品。

## 本轮限制与下一阶段

本轮是通用恢复基础，不是与独立 Pi 客户端完全等价的完整开发环境。

- 仍使用已有 CAD 工具词汇，没有任意 API 编程能力；不能自动解决尚未提供的扫掠、放样等接口缺口。
- 首期仅新建零件、单配置、无外部/辅助引用、可完整读取的二维线弧草图。装配体、工程图和在活动草图中分支不支持。
- 新副本不继承原文档的端面缓存和可编辑实体引用；当前候选从稳定基准面建立，后续需要增加跨副本的确定性重新定位能力。
- 当前可自动替换尚未采用的候选阶段；不提供对任意多个已采用阶段的自动回退或重写，后续需要显式检查点分支与依赖重验。
- 接受模型仍打开于 SolidWorks，原件和候选均保留；本轮没有自动清理大量副本或保存最终交付文件。
- 实际只读证据加原生复制不是一般几何等价证明，也不是生产可制造性认证。

下一阶段：将受控试验服务接成 Pi 原生可调用的建模工具；增加宿主审核的可编程 CAD 能力描述与受控文档资料查询；扩充局部位置、角度、切向连续性和连接关系的独立验收；允许显式选择已验证检查点创建新分支并重验依赖。仍不得让推理模型绕过最终本地安全与验收规则。

### 性能优化顺序（尚未实现）

当前一个三步成功候选（局部检查不含外廓测量）约触发 12 次完整模型观察：宿主基线 1 次、创建副本内部 4 次、各步骤前后 6 次、采用 1 次；普通 worker 还为工具调用附加前后快照。失败返回另需观察原基线。成本不仅来自建模 API，也来自重复验证。

1. 先为 `model.observe` 去除外围重复快照，保留身份/配置/状态戳前后核验与失败语义。上述例子中 7 次完整观察可少做 14 次普通快照，不减少严格观察本身；外廓测量随后单独审查，不直接推广到全部只读工具。
2. 由 worker 持有一次完整观察的可信回执；只在文档身份、配置、更新戳以及选择/活动草图上下文仍一致时复用，不信任 Agent 提交的缓存。
3. 副本创建后的独立读回、写操作后的验证、返回原基线后的验证不可直接删掉；不把原件快照套用到新副本。
4. 对创建副本的各子步骤记录耗时和公开心跳，再验证真正进程 RPC 的 120 秒边界。客户端期限包含排队与锁等待，不能只比较 CAD 子步骤时间；本地 InlineWorker 实机冒烟的总预算不等于验证了桌面客户端超时机制。

## 验收方式

- 自动故障注入：局部检查失败、原生失败后状态改变、错误合并、数值噪声、缺测、失败后改程序、重复候选、连续无进展、停止与重启、外部切换、权限、目录注入。
- 假队列 RPC：验证串行门、worker 启动参数、严格布尔值、取消与晚到响应。没有真实模型请求或 CAD 修改。
- 原生冒烟脚本需显式 `--execute`：只在新建测试零件及其副本上建模；原用户模型不修改、不保存、不关闭；使用确定性测试后端以隔离 CAD 机制和大模型质量，不把它称作真实模型自主建模验收。
- 全量测试、Ruff、mypy、编译检查完成后，在迭代报告记录实际结果。没有通过的验收不得以计划或假测试代替。
